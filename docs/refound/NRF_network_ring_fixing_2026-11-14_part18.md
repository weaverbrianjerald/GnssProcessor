### 125. 2026-11-18: the saved state of the chain and the ring fix (card CHA step S7 (b); pre-registered)

**Why.** A run resumed from a snapshot starts the chain's tree memory and the whole ring fix empty (card CHA, part 2, P9; part 3, the list of step S7 (a)): every held link and its integers, the settled flags' waits, the untied satellites' moves, the vertices seen in earlier trees and the pinned lives of the tree edges; and the loader drops the root and merge rows whenever a snapshot is written. A restarted network (a reboot, a streamed service) therefore loses every held integer and fixes again from nothing. The author's word of 2026-11-18 moved the saved state up the order (card CHA, the order change of 14:15).

**The build** (default off, the precedent of card CRS2's hold capture and restore). Two keys:
- `network.state_snapshot_chain_capture`, the write side: the snapshot carries the memory below as records of their own, and the warm-resume fingerprint carries a token for each key that shapes that memory (the ring fix's keys, the chain's event rows, the pair families, the phase-family table), so a snapshot written under other settings cold-starts the memory.
- `network.resume_chain_restore`, the read side: a warm resume restores those records. A snapshot without them restores none, and a run-start line says so (the rows then run without memory, as today).

The memory (the list of card CHA S7 (a)):
- the chain: the vertices seen in earlier trees (satellite bands and receiver bands), the last election's tree roots, the root row's pinned receiver phase-bias targets, the pinned lives of the tree edges, the arcs' anchor ages and the emitter's anchor baseline;
- the ring fix: the links (held integers, streaks, decision stamps, roots, the monitor's and the near-null guard's state), the last tree times, the certified edges, the settled sets and their waits, the cascade links, the first epoch, the previous targets, the untied satellites' times, and the two hand-offs (the pending moves, the pending re-opens); not its run counters, which each leg reports for itself;
- the emitter's state that depends on held values: the step declaration's baselines and pending release marks, the unsettled steps' last flags, the continuity guard's runs, datums and holds;
- the broadcast group-delay latch (RF-0c): each satellite's latched value and the window it was latched over.

With the capture key, the loader keeps the root and merge rows when a snapshot is written (their memory travels with it). The ledger rows of both keys are UNVALIDATED. Unit cases: a round trip of every new record, and the fingerprint's tokens.

**The group-delay latch** (the manager's point 3, checked in the code). The snapshot carries no group delay and no window: the setup latches into `setup.sat_gf_target_m`, which no record writes, over the window [first epoch, first epoch + `processing.max_duration_s`) of the run (`ApplicationNetworkSetup.cpp`, the window and the latch). A resumed leg runs the setup again and latches over its own window. The O3 rule named beside it is a rule of the record's time (a broadcast record takes force at its clock epoch, `navAvailabilityGpsSeconds`): a resumed leg feeds the staged records by the same rule from its first epoch, so the rule itself needs nothing saved. The latch therefore belongs to the saved memory: with the restore key, a resumed leg takes the saved values in place of its own latch, and a run-start line names the saved window and the satellites restored. The identity test gives the uninterrupted run and the saving run one window: the uninterrupted run is the saving run (it writes the snapshot at 2 h and continues to 3 h), so its latch is the 3 h one, and the resumed leg restores that latch. If rule change 11 (card CHA part 3: a causal latch, so that a short run is a prefix of a long one) is approved and built before this step, the test also runs with it.

### 125.1 2026-11-18: the manager's word on section 125, before any run

**Accepted.** The identity read in three parts (B2a, B2b, B2c, with B0, B1 and B3): the discrete state at the level today's resume can keep, B1 measured first and kept in the section as the reason.

**B4, added before any run: the replay as a proof.** On m1 and on n147, the same leg run twice from one seed is identical in products and every trace (`nom_td_gate.py --whole --mask-time`), and the matched null run twice likewise.
