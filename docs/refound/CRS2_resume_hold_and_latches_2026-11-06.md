## 1. The question

Card CRS measured and attributed the metre the leg consumer carries from its first epoch. Two defects meet at the seam. The producer's hold is `Persist::ColdStart` in every row, so the resumed producer first-sights every held key: generation 1, held value equal to the current estimate, a re-level of up to 21 m per key that the consumer's hold reaction ignores by design (the generation is unchanged). The consumer snapshot carries no initializer latch, so the restored consumer re-runs its first-epoch seeds and overwrites the restored Galileo inter-system bias and both receiver code biases with one epoch of code under the restored tight covariance. On `g` the second defect is masked by the first (the seam mark's counter steps re-inflate exactly the re-seeded states), so the producer fix alone was predicted to move the `g` legs from 1.1 m toward 14 m. This card builds both and measures them together and apart.

## 2. Design

### 2.1 Producer: the hold in the snapshot

Four entity fields change from `Persist::ColdStart` to `Persist::Record` (`src/core/network/state/Entities.cpp`), each with its snapshot tag under the existing header, the RS-3 / RS-5 precedent:

| field | entity | tag | content |
|---|---|---|---|
| `pb_hold` | satellite signal | `PH` | `<sat>|<signal>`, generation, held value, last emission time, and the transfer bookkeeping (`frz_ref`, `frz_ok`, `frz_last`, `smh_reverted`, `smh_last`, `smh_ref_pending`, `smh_on_clone`, `smh_lah_last`) |
| `pb_hold_frz_M` | constellation | `PHM` | the accumulated common emitted-clock step M |
| `pb_hold_prev_clock_m` | satellite | `PHC` | the emitted clock at the satellite's previous emission (the coupled-mark baseline) |
| `pb_hold_frz_prev_clk` | satellite | `PHF` | the emitted clock at the previous emitted epoch (the common-step baseline) |

Written under `network.state_snapshot_hold_capture` (write side only: products and traces byte-identical), restored under `network.resume_hold_restore` before the first epoch, after the emit-layer restore. A file without the rows is inert and says so. `networkPbHold` then finds each restored key present: no first sighting, no generation start, the held emission `held_m + (c~(t) - frz_ref)` with the restored M and references, so the first leg emit continues the seed's wire. The resume seam mark (`network.resume_pb_seam_mark`) tests the first emit against the restored emitter baselines and is expected to find no key over its threshold.

The smoothed hold's clock clone (`smh_clone`, a coupling row on the shared border, stamped on the write epoch's stash) stays `ColdStart`: the restore queues a birth (`smh_pending`, and the block clone's `smh_block_pending`) for every restored key in its restored generation, the rule a generation start applies, so the clone is born at the first post-resume stash at which the anchor holds the clock. Between the restore and the birth the key carries the hold family's transfer, the continuous switch the hold already makes when a clone dies, and the switch back onto the new clone is continuous as well (the transfer at a clone's birth equals the bridge's).

### 2.2 Consumer: the seed latches in the consumer snapshot

The consumer snapshot (`include/realtime/RtStateSnapshot.hpp`) gains one record, `I,<latch>,0|1`, for the four `StateInitializer` latches (`isb`, `phase_clock`, `code_bias`, `clock_seed`), written under `realtime.state_snapshot_latch_capture`. Under `realtime.state_snapshot_latch_restore` a restore sets each latch the file holds true, with one scope rule: the code-bias latch is set under the full restore scope only, because the core scope re-creates the receiver code-bias states per epoch and they need their seed. A file without `I` rows is inert and says so. The rule is a pure function with its own unit test.

### 2.3 Not built

Card CRS item 3 (the consumer's hold ledger, the ionosphere elevation memory and the epoch-cadence window in the consumer snapshot) is not built: a restored consumer still reads every held key's generation at its first epoch as a first sighting, so a generation edge inside the outage is still missed. Reported from the leg consumer's run-end line, not fixed.
