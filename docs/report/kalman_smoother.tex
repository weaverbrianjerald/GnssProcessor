\section{Estimation engine: the Kalman filter and RTS smoother}\label{sec:kf}
% ============================================================
%  Estimation engine: the Kalman filter and RTS smoother
% ============================================================

This section documents the engine's recursive estimator.  It is a
variable-dimension extended Kalman filter (EKF) with an optional
prior-anchored iterated (IEKF) relinearisation pass, robust gating of
post-fit residuals, and a backward Rauch--Tung--Striebel (RTS) smoother
for post-processing.  The state vector $\stateV$ is the uncombined PPP /
PPP-RTK parameterisation of \dcref{sec:state}{the state-vector-layout
section of the Foundations document}: receiver position (and optionally
velocity), receiver clock and per-system time offsets, zenith wet
troposphere and gradients, per-satellite slant ionosphere, receiver and
satellite code and phase biases, and one float ambiguity per tracked
carrier.  The dimension changes from epoch to epoch as satellites rise
and set and as ambiguities are reset.  \texttt{filter/StateManager} owns
the layout and the dynamic key$\to$index maps.  The filter operates on
that state and assumes no fixed indices
(\texttt{src/core/filter/KalmanFilter.cpp}).

Throughout we write $\Fmat$ for the state-transition matrix, $\Qmat$
for the discrete process-noise covariance, $\Rmat$ for the
measurement-noise covariance, $\Smat$ for the innovation covariance,
$\Kgain$ for the Kalman gain, and $\innov$ for the innovation
(measurement minus predicted measurement).  Predicted (a-priori) and
updated (a-posteriori) quantities use the tilde/hat and $k|k{-}1$ /
$k|k$ conditioning convention fixed in \dcref{sec:notation}{the
notation-and-conventions section of the Foundations document}.

\subsection{Time update}\label{sec:kf-predict}

\paragraph{State transition.}
The transition matrix $\Fmat(\dt)$ for epoch interval
$\dt = t_k - t_{k-1}$ is identity plus a small number of coupling
blocks, assembled by \texttt{StateManager::getTransitionMatrix}
(\texttt{src/core/filter/StateManager.cpp}).  The kinematic-integrator
off-diagonal couplings are
\begin{equation}
\Fmat[\,\rxpos,\bm{v}\,] = \dt\,\bm{I}_3,
\qquad
\Fmat[\,\sLight\mathrm{d}t,\;\sLight\dot{\mathrm{d}t}\,] = \dt,
\qquad
\Fmat[\,\sLight\delta t^{(g)},\;\sLight\dot{\delta t}^{(g)}\,] = \dt,
\label{eq:kf-F-blocks}
\end{equation}
present only when the corresponding rate state exists
(\texttt{hasVelocity()}, clock-rate, per-system rate).  A fourth coupling
appears when the constant-velocity slant-iono model is armed
(\texttt{estimation.enable\_iono\_rate}, default off): a per-satellite
level/rate integrator
\begin{equation}
\Fmat[\,I^{\sat},\;\dot I^{\sat}\,] = \dt
\qquad\text{for every non-frozen-pivot satellite,}
\label{eq:kf-F-iono}
\end{equation}
which gives $I^{\sat}(k{+}1) = I^{\sat}(k) + \dt\,\dot I^{\sat}(k)$.  Every
other state has $\Fmat = \bm{I}$ and is a random walk with constant
mean: ambiguities, zenith wet delay, gradients, code and satellite
biases, any inter-system offset without a rate, and (without
\texttt{enable\_iono\_rate}) the per-satellite ionosphere.

Under the BSSD (single-difference) parameterisation some states are
unobservable, because their $\jacH$ columns are zero: the receiver
clock, the phase clock (\texttt{getPhaseClockIndex}), the inter-system
offsets, and the frozen-pivot per-satellite ionosphere
(\texttt{getFrozenPivotSatellites}).  Their rows in
\Cref{eq:kf-F-blocks} are suppressed.  After propagation their
cross-covariances are set to zero and their diagonal variances are kept
(the \texttt{freeze\_state} block in
\texttt{src/core/filter/KalmanFilter.cpp}).

The iono level/rate coupling of \Cref{eq:kf-F-iono} is \emph{not}
disabled under BSSD.  The slant-iono level stays observable under
single-differencing, since only the pivot column is zero, so every
satellite other than the frozen pivot keeps its integrator.  The frozen
pivot is skipped.  Its rate is held at $(0,0)$ and its process noise is
suppressed, so the coupling cannot move the pivot level away from the SD
datum.

The propagation itself is the standard EKF time update
\begin{empheq}[box=\fbox]{align}
\tilde{\stateV}_{k|k-1} &= \Fmat(\dt)\,\hat{\stateV}_{k-1|k-1}, \\
\tilde{\covM}_{k|k-1}    &= \Fmat(\dt)\,\covM_{k-1|k-1}\,\Fmat(\dt)^{\Tr}
                            + \Qmat(\dt),
\label{eq:kf-predict}
\end{empheq}
implemented in \texttt{KalmanFilter::predict}.  A non-positive $\dt$
(a duplicate or out-of-order epoch) does nothing: the routine returns
before \Cref{eq:kf-predict}.

\paragraph{Process-noise model.}
The discrete process noise $\Qmat(\dt)$ is built from continuous
spectral densities by \texttt{StateManager::getProcessNoiseMatrix}.
Two block structures appear.  Pure random-walk states have a scalar
discrete variance increment
\begin{equation}
\Qmat_{ii} = \spd{i}\,\dt,
\label{eq:kf-Q-rw}
\end{equation}
where $\spd{i}$ is the continuous variance rate
($\mathrm{m}^2/\mathrm{s}$) read from \texttt{filter.process\_noise.*}.
Representative entries are zenith wet troposphere
(\texttt{troposphere\_q}), the receiver code bias
(\texttt{code\_bias\_q}), the satellite \emph{code} bias
(\texttt{sat\_bias\_q}, applied to
\texttt{StateManager::sat\_bias\_indices\_}), the satellite \emph{phase}
bias (\texttt{sat\_phase\_bias\_q}, a separate density on the separate
\texttt{sat\_phase\_bias\_indices\_} map),
phase clock (\texttt{phase\_clock\_q}), and the float ambiguity
(\texttt{ambiguity\_q}).  Both satellite-bias blocks, and the
satellite-clock block beside them, set $\Qmat$ to zero for a frozen-pivot
satellite.  The frozen state is held at (value, variance) $=(0,0)$ as
the datum, and any process noise would move it off that datum.  The
ambiguity density defaults to a numerical floor ($10^{-12}$), not a
physical value.  Per-key overrides are supported for reseeding
individual arcs.  The per-satellite
slant ionosphere uses a random walk whose zenith density is mapped to
the slant by the squared obliquity factor,
\begin{equation}
\Qmat_{ii}
  = \frac{\spd{\mathrm{iono}}}{\sin^2\theta^{\sat}}\,\dt,
\qquad
\sin^2\theta^{\sat} \ \text{floored at } 10^{-2}\ (\theta\!\approx\!5.7^\circ),
\label{eq:kf-Q-iono}
\end{equation}
with $\spd{\mathrm{iono}} = $ \texttt{ionosphere\_q} and optional
per-satellite overrides driven by the adaptive-iono scheme.  Under the
constant-velocity model of \Cref{eq:kf-F-iono} this random walk is used
only for satellites without a rate state.  Otherwise the level/rate pair
takes the CWNA block of \Cref{eq:kf-Q-cwna} below, with the acceleration
PSD scaled by obliquity,
$q = \spd{\dot{\mathrm{iono}}}/\sin^2\theta^{\sat}$, where
$\spd{\dot{\mathrm{iono}}} = $ \texttt{process\_noise.iono\_rate\_psd}
(an acceleration PSD, $\mathrm{m}^2/\mathrm{s}^3$, default $10^{-10}$).
The adaptive-monitor override enters this branch as the
\emph{dimensionless} ratio $q_{\mathrm{ov}}/\spd{\mathrm{iono}}$, which
multiplies the rate PSD.  The Sage--Husa storm response therefore acts
on $\dot I^{\sat}$, not on the level.

Coupled position/velocity, clock/clock-rate, inter-system offset/rate,
and, under \texttt{enable\_iono\_rate}, slant-iono level/rate pairs
use the continuous white-noise-acceleration (CWNA,
integrated-random-walk) discretisation.  For a coupled pair $(\xi,
\dot\xi)$ driven by acceleration PSD $q$,
\begin{equation}
\Qmat_{[\xi,\dot\xi]}
  =
  \begin{bmatrix}
    \tfrac{1}{3}\,q\,\dt^{3} & \tfrac{1}{2}\,q\,\dt^{2} \\[2pt]
    \tfrac{1}{2}\,q\,\dt^{2} & q\,\dt
  \end{bmatrix},
\label{eq:kf-Q-cwna}
\end{equation}
with $q$ given by \texttt{acceleration\_psd\_q} (position/velocity, the
$3\times3$ block-diagonal extension of \Cref{eq:kf-Q-cwna} over the ECEF
axes), \texttt{clock\_rate\_q}, \texttt{system\_time\_rate\_offset\_q},
and the obliquity-scaled \texttt{iono\_rate\_psd}$/\sin^2\theta^{\sat}$
respectively.  When the velocity state is present the rate-free
position density \texttt{position\_q} is unused.  Baseline
(double-difference) mode reduces $\Qmat$ to the position block, a
per-ambiguity random-walk term, and an optional differential-ZWD entry
$\Qmat_{ii} = \sigma^2\dt$ governed by
\texttt{baseline.differential\_tropo\_process\_noise\_m\_per\_sqrt\_s}.

\paragraph{Scope: the recursive estimator only.}
These densities apply to the \emph{recursive} estimator.  The network
producer does not run a \texttt{KalmanFilter}.
\texttt{getTransitionMatrix} and \texttt{getProcessNoiseMatrix} are
called only from \texttt{KalmanFilter::predict} / \texttt{predictImu} /
\texttt{predictAided} and from the smoother's
\texttt{Application::capturePriorSnapshot}.  The producer solves
per-epoch normal equations for corrections to each station's
linearisation point.  It links epochs with explicit information-form
carry priors of effective variance
$\mathrm{var}_{\mathrm{eff}} = \mathrm{var} + q\,\dt$, not through
$\Qmat(\dt)$ (\dcref{sec:net}{the network-mode document}).  There the
satellite-side densities \texttt{sat\_clock\_q},
\texttt{sat\_phase\_bias\_q} and \texttt{sat\_code\_bias\_q} are read as
those carry rates.  They can also be set through the network-scoped
\texttt{network.process\_noise} class table, which is always active.  Its
per-class fallbacks equal the legacy \texttt{filter.process\_noise.*}
defaults, so an unmodified config gives the same values either way.

\paragraph{Aided time update.}
When inertial aiding is active, \texttt{KalmanFilter::predictImu}
mechanises the nominal position, velocity, and attitude (strapdown).  It
inserts a $15\times15$ INS error-state transition $\bm{\Phi}$ and noise
$\Qmat_{\mathrm{ins}}$, with error order
$[\delta\bm{p},\,\delta\bm{v},\,\delta\bm{\psi},\,\delta\bm{b}_a,\,
\delta\bm{b}_g]$, into the GNSS-dimensioned $\Fmat$ and $\Qmat$ over the
integrated interval.  \Cref{eq:kf-predict} then runs on the full state,
followed by the symmetrisation
$\covM \leftarrow \tfrac12(\covM + \covM^{\Tr})$.  The general
\texttt{predictAided} path does the same for any aiding source.  With no
aiding payload it calls the GNSS-only \Cref{eq:kf-predict} and gives a
byte-identical result.

\subsection{Measurement update}\label{sec:kf-update}

The measurement update (\texttt{KalmanFilter::update}) is a
\emph{batch} update: all observation rows of the epoch are processed
together, not one at a time.  A sparse-$\jacH$ optimisation speeds up
the four products that involve the design matrix ($\jacH\covM$,
$\jacH\covM\jacH^{\Tr}$, $\Kgain\jacH$, and the $\jacH$ parts of the
gain).  It agrees with the dense computation to a $10^{-12}$ structural
threshold (\texttt{src/core/filter/KalmanFilter.cpp}).

Given the design matrix $\jacH$ from the linearisation of the
\dcref{eq:obs-code}{code observation equation} and
\dcref{eq:obs-phase}{phase observation equation} of the Foundations
document (position rows $-(\los^\sat_{\hat{\rx}})^{\Tr}$, the
\dcref{eq:geom-linear}{linearised geometric range there}), the
innovation $\innov$ (\texttt{measurement.innovations}), and the
measurement-noise covariance $\Rmat$ (a full matrix when supplied,
otherwise the diagonal $\Rmat = \operatorname{diag}(\sigma^2_{\rx,\sat,\sigl})$
of the \dcref{eq:noise-model}{stochastic noise model there}), the
innovation covariance and gain are
\begin{align}
\Smat   &= \jacH\,\tilde{\covM}_{k|k-1}\,\jacH^{\Tr} + \Rmat,
\label{eq:kf-S}\\
\Kgain  &= \tilde{\covM}_{k|k-1}\,\jacH^{\Tr}\,\Smat^{-1}.
\label{eq:kf-gain}
\end{align}
The gain is not formed by inverting $\Smat$.  $\Smat$ is symmetric, so
the engine factorises it once with an $\mathrm{LDL}^{\Tr}$ decomposition
and obtains $\Kgain = \big(\Smat^{-1}\jacH\tilde{\covM}\big)^{\Tr}$ from
one solve against $\jacH\tilde{\covM}$
(\texttt{ldlt.solve(HP).transpose()}).  If the factorisation fails it
falls back to a complete-orthogonal (pseudo-inverse) solve.  The state
update is
\begin{equation}
\delta\stateV = \Kgain\,\innov,
\qquad
\hat{\stateV}_{k|k} = \tilde{\stateV}_{k|k-1} + \delta\stateV.
\label{eq:kf-state-update}
\end{equation}

\paragraph{Joseph-form covariance update.}
The covariance update uses the \emph{Joseph} form, not the short form
$(\bm{I} - \Kgain\jacH)\tilde{\covM}$:
\begin{empheq}[box=\fbox]{equation}
\covM_{k|k}
  = (\bm{I} - \Kgain\jacH)\,\tilde{\covM}_{k|k-1}\,
    (\bm{I} - \Kgain\jacH)^{\Tr}
    + \Kgain\,\Rmat\,\Kgain^{\Tr}.
\label{eq:kf-joseph}
\end{empheq}
The Joseph form keeps the covariance symmetric and positive
semi-definite for any gain.  That property is needed because the robust
paths of \Cref{sec:kf-gating} use a gain that is not the optimal one.
The result is symmetrised again,
$\covM \leftarrow \tfrac12(\covM + \covM^{\Tr})$, to remove round-off.
The factor $(\bm{I} - \Kgain\jacH)$ is built from the sparse
$\Kgain\jacH$ product by adding one on the diagonal.  The same kernel,
with the explicit gain $\Kgain = \covM\jacH^{\Tr}\Smat^{-1}$, is the
static routine \texttt{josephPseudoUpdate}.  It is reused for scalar
pseudo-observation constraints (for example the GIM ionosphere prior via
\texttt{applyPseudoObservation}) and for the IEKF pass of
\Cref{sec:kf-iekf}.

\paragraph{Post-fit residuals.}
After the update the post-fit residuals and their (diagonal) covariance
are
\begin{equation}
\bm{r} = \innov - \jacH\,\delta\stateV,
\qquad
S_{r,ii} = R_{ii} - \big(\jacH\,\covM_{k|k}\,\jacH^{\Tr}\big)_{ii},
\label{eq:kf-postfit}
\end{equation}
By default only the diagonal of $S_r$ is formed.  The full symmetrised
$S_r = \Rmat - \jacH\,\covM_{k|k}\,\jacH^{\Tr}$ is formed and stored when
two conditions hold: the off-diagonal-$R$ kernel is enabled
(\texttt{enable\_full\_r\_kernel}, default off), \emph{and} a dense
$\Rmat$ was supplied (BSSD and baseline-DD epochs, whose $\Rmat$ carries
SD/DD cross-covariance).  The redundancy and $w$-test QC of
\Cref{sec:kf-gating} then account for correlated observations through
$S_r^{-1}$.  The diagonal, and so \Cref{eq:kf-sres}, is the same either
way.  The standardised residual used for gating (\Cref{sec:kf-gating})
is
\begin{equation}
\sres_i
  = \frac{r_i}{\sqrt{\max\!\big\{\,S_{r,ii},\,R_{ii},\,10^{-12}\,\big\}}}.
\label{eq:kf-sres}
\end{equation}
The denominator is floored at the \emph{working} $R_{ii}$, the inflated
noise actually used in $\Rmat$, not the formal noise.  This is a
deliberate compromise.  When an ambiguity absorbs the measurement
(double-differenced phase with an ambiguity gain near one), the rigorous
denominator $S_{r,ii}$ shrinks toward $R\,\Smat^{-1}R$, and residuals
near zero would register as outliers of many $\sigma$.  The strictly
correct standardisation uses $S_{r,ii}$ alone.  The floor gives up that
rigour for stability, and the source code says so.

\subsection{Iterated relinearisation (IEKF)}\label{sec:kf-iekf}

When the initial position is far from the truth, one linearisation of
the \dcref{eq:geom-linear}{geometric-range relation of the Foundations
document} per epoch may not be enough.  When
\texttt{processing.relinearize\_geometry} is enabled, and the run is not
tightly-coupled IMU, the engine performs a prior-anchored iterated
update (a Gauss--Newton, or iterated EKF, step) after the primary
update.

\paragraph{Anchor.}
The iteration is anchored to the \emph{stored pre-update prior}
$(\stateV^{-}, \covM^{-})$ that the primary update
\Cref{eq:kf-predict,eq:kf-joseph} used.  It is captured only when
relinearisation is armed (\texttt{getLastUpdatePriorX} /
\texttt{getLastUpdatePriorP}).  It is the prior \emph{after} any in-epoch
ambiguity augmentation and outlier reset, so its dimension matches the
posterior.  It is not a snapshot from the top of the epoch loop.

\paragraph{Gauss--Newton step.}
Let $\stateV_i$ be the current linearisation iterate (the committed
state at which \texttt{measurement} was linearised, with innovations
$\bm{z} - h(\stateV_i)$ and $\jacH = \partial h / \partial \stateV
\big|_{\stateV_i}$).  The prior-anchored iterate
(\texttt{KalmanFilter::updateFromPrior}, via \texttt{josephPseudoUpdate})
is
\begin{empheq}[box=\fbox]{align}
\innov &= \big(\bm{z} - h(\stateV_i)\big) - \jacH(\stateV^{-} - \stateV_i),
\label{eq:iekf-innov}\\
\Kgain &= \covM^{-}\jacH^{\Tr}\big(\jacH\covM^{-}\jacH^{\Tr} + \Rmat\big)^{-1},
\qquad
\stateV^{+} = \stateV^{-} + \Kgain\,\innov,
\label{eq:iekf-gain}\\
\covM^{+} &= (\bm{I} - \Kgain\jacH)\,\covM^{-}\,(\bm{I} - \Kgain\jacH)^{\Tr}
            + \Kgain\,\Rmat\,\Kgain^{\Tr}.
\label{eq:iekf-cov}
\end{empheq}
The offset term $-\jacH(\stateV^{-} - \stateV_i)$ in \Cref{eq:iekf-innov}
expresses the innovation about the fixed prior, which makes this a MAP
(Gauss--Newton) iteration.  $\Kgain$ and
$(\bm{I} - \Kgain\jacH)\covM^{-}$ are always computed from the same
fixed prior $(\stateV^{-}, \covM^{-})$, so the covariance does
\emph{not} shrink a second time and no information is counted twice.

\paragraph{Firing condition.}
The driver \texttt{Application::runGeometryRelinearization}
(\texttt{src/core/app/Application.cpp}) fires the iteration when all of
the following hold:
\begin{enumerate}[leftmargin=*, itemsep=0pt]
\item \texttt{processing.relinearize\_geometry} is on and a prior was
      stashed at the primary update;
\item the position change since the primary update exceeds a
      data-dependent threshold, \texttt{relinearize\_dpos\_threshold\_phase\_m}
      (default $1\,\mathrm{m}$) when phase is present, or
      \texttt{relinearize\_dpos\_threshold\_code\_only\_m} (default
      $100\,\mathrm{m}$) for code-only epochs;
\item the per-run cap \texttt{relinearize\_max\_count}
      ($-1 =$ unlimited) is not exhausted.
\end{enumerate}
The inner loop recomputes the geometry and re-applies
\Cref{eq:iekf-innov,eq:iekf-gain,eq:iekf-cov} against the \emph{fixed}
exclusion set from the primary update.  It runs at most five iterations
and stops when the position step falls below $10^{-4}\,\mathrm{m}$.
GNSS geometry is nearly linear at the metre level, so one pass usually
converges, and the threshold of item~2 means the iteration rarely fires.
The tightly-coupled IMU configuration takes a single legacy \emph{naive}
second pass, re-applying the measurement against the posterior, because
error-state attitude and bias feedback conflicts with re-deriving the
update from the prior.

\subsection{Innovation and residual gating}\label{sec:kf-gating}

The engine performs \emph{no} $\chi^2$ test on the innovation covariance.
Outlier rejection (\texttt{KalmanFilter::validatePostFitResiduals}) tests
the standardised \emph{post-fit} residuals $\sres_i$ of \Cref{eq:kf-sres}
against a fixed scalar threshold.  Robust median-based detectors for
pivot slips supplement it.  The two top-level thresholds are hardcoded
\texttt{GnssConfig} defaults (\texttt{residual\_threshold\_} $= 6.0$ and
\texttt{bad\_meas\_percent\_} $= 0.5$ in
\texttt{src/core/config/GnssConfig.cpp}).  They are not exposed to JSON,
so there are no config keys of those names.  The per-row rejection
threshold is $\sres_{\max} = 6.0$ (read at runtime via
\texttt{getResidualThreshold}).  The fraction that triggers a complete
reset is $0.5$ (\texttt{getBadMeasPercent}).  The Baarda data-snooping
gate below, which is exposed to JSON, can replace both the dispatched
row and the criterion.

\paragraph{Per-row rejection.}
If $\max_i |\sres_i| > 6.0$, the worst row is handled according to its
type.  A phase outlier triggers an ambiguity reset, with BSSD pivot
handling and a sub-cycle $\lambda$-fraction floor.  A code outlier is
excluded from the epoch.  Correlated phase rows of the same satellite on
other bands are reset with it.

\paragraph{Baarda data-snooping gate (optional override).}
When \texttt{estimation.enable\_data\_snooping} is set, the fixed-$\sigma$
gate triple $(\text{gate stat},\text{gate row},\text{gate crit}) =
(\max_i|\sres_i|,\,\arg\max,\,6.0)$ is \emph{replaced} in
\texttt{validatePostFitResiduals} by the Baarda $w$-test.  The test runs
over \emph{checkable} rows, those whose redundancy
$r_i = S_{r,ii}/R_{ii}$ is at least $0.1$.  Rows with lower redundancy
are skipped, because a blunder there goes into the estimate and not the
residual.  The row with the largest $|w_i|$ is selected, and the gate
fires when $|w_i| > $ \texttt{estimation.data\_snooping\_critical}
(default $3.29$).  Both the criterion \emph{and} the dispatched row can
therefore differ from the $\sigma$ gate.  The handling of the selected
row by type is unchanged.  The $w$-test statistic and
redundancy are produced by the a-posteriori QC diagnostics layer
(\texttt{computeResidualQc\_}, gated by
\texttt{estimation.enable\_variance\_factor}): the variance factor
$\hat\sigma_0^2 = \big(\sum_i v_i^2/R_{ii}\big)/\mathrm{dof}$, the per-row
redundancy $r_i$, the $w$-test, and the minimal detectable bias (MDB).
This layer accounts for a correlated $R$ through $S_r^{-1}$ when the
full-$R$ kernel is active (see \Cref{eq:kf-postfit}).

\paragraph{Complete-reset backstop.}
If the number of rejected rows exceeds $0.5 \times{}$ the original
observation count (before any rows were removed), the filter covariance
is re-inflated (\texttt{resetFilterCovariance}).  This is a hard reset.
In the smoother it marks a segment boundary
(\Cref{sec:kf-smoother}).

\paragraph{Robust pivot-slip detectors (BSSD).}
Before the per-row gate, single-difference phase rows are grouped by
(pivot, signal) and screened for a pivot slip common to the group, using
median and median-absolute-deviation (MAD) statistics.  A forced pivot
handover fires when four conditions hold: the group is large enough, a
majority of its rows exceed the threshold, the group median exceeds a
metre-scale floor, and the MAD-to-median ratio is small.  A small ratio
means a tight cluster, which indicates a common shift and not scattered
noise.  Cross-band pooled and code-side variants apply similar tests
with their own floors.  Slips on non-pivot satellites across several
bands are confirmed by integer-cycle consistency:
$|r|/\lambda_{\mathrm{band}}$ must round to the same nonzero integer on
each band.

\paragraph{Down-weighting (not gating).}
Two paths inflate $\Rmat$ and do not reject.  A persistent EWMA-bias term
adds the squared mean bias to $R_{ii}$ once an arc has warmed up.  A
Huber post-fit scheme inflates $R$ for sub-cycle rows whose $|\sres_i|$
exceeds the Huber knee, either once on the innovation or iteratively on
the post-fit residual (IRLS), toggled by
\texttt{enable\_huber\_r\_inflation} and
\texttt{enable\_huber\_innovation}.  Both change the working $\Rmat$ used
in \Cref{eq:kf-S,eq:kf-sres}.  The standardised residual is therefore
scaled by the working noise, not the formal noise.

\subsection{Backward RTS smoother}\label{sec:kf-smoother}

In post-processing modes, enabling \texttt{processing.run\_smoother}
runs a fixed-interval Rauch--Tung--Striebel recursion
\cite{rauch1965} over the stored forward trajectory
(\texttt{include/filter/Smoother.hpp},
\texttt{src/core/filter/Smoother.cpp}).  The flag is forced off under
\texttt{AppMode::RealTime}, because smoothing uses future data.

\paragraph{Forward-pass capture.}
The backward pass does not reconstruct the a-priori from $\Fmat$ and
$\Qmat$.  The forward pass stores, per epoch, the one-step prediction
$\tilde{\stateV}_{k|k-1}, \tilde{\covM}_{k|k-1}$, the posterior
$\hat{\stateV}_{k|k}, \covM_{k|k}$, the matrix $\Fmat_k$, and all core and
dynamic key$\to$index maps (\texttt{capturePriorSnapshot} /
\texttt{capturePosteriorSnapshot} in
\texttt{src/core/app/Application.cpp}).  The order of capture makes the
stored prior equal to $\Fmat_k\hat{\stateV}_{k-1|k-1}$.  The a-priori is
recorded immediately after \texttt{predict()}, before any cycle-slip
reseeding or measurement update.  The a-posteriori is recorded
\emph{before} integer ambiguity resolution, so the smoother uses
\emph{float} ambiguities only.

\paragraph{Recursion.}
Initialised at the terminal posterior
$\smooth{\hat{\stateV}}{N} = \hat{\stateV}_{N|N}$,
$\smooth{\covM}{N} = \covM_{N|N}$, the backward recursion is
\begin{empheq}[box=\fbox]{align}
\gainS_k
  &= \covM_{k|k}\,\Fmat_{k+1}^{\Tr}\,\tilde{\covM}_{k+1|k}^{-1},
\label{eq:rts-gain}\\
\smooth{\hat{\stateV}}{k}
  &= \hat{\stateV}_{k|k}
     + \gainS_k\big(\smooth{\hat{\stateV}}{k+1} - \tilde{\stateV}_{k+1|k}\big),
\label{eq:rts-state}\\
\smooth{\covM}{k}
  &= \covM_{k|k}
     + \gainS_k\big(\smooth{\covM}{k+1} - \tilde{\covM}_{k+1|k}\big)
       \gainS_k^{\Tr}.
\label{eq:rts-cov}
\end{empheq}
The smoother gain $\gainS_k$ is computed by an $\mathrm{LDL}^{\Tr}$ solve,
not an explicit inverse.  The predicted covariance is symmetrised, then
$\gainS_k = \big(\tilde{\covM}_{k+1|k}^{-1}(\covM_{k|k}\Fmat^{\Tr})^{\Tr}\big)^{\Tr}$
via \texttt{ldlt.solve(...).transpose()}.  The smoothed covariance
\Cref{eq:rts-cov} is symmetrised after the update.  If the factorisation
fails, the step is skipped and epoch $k$ keeps its forward posterior.

\paragraph{Variable-dimension reconciliation.}
Because $\dim\stateV_k \neq \dim\stateV_{k+1}$ in general,
\Cref{eq:rts-gain,eq:rts-state,eq:rts-cov} are restricted at each step
to the \emph{common-key subspace}, the states present at both $k$
and $k{+}1$, found by intersecting the dynamic key$\to$index maps
(\texttt{collectCommonIndices}, less any keys in the handover exclusion
set of the segment-boundary paragraph below).  Let $\bm{\Pi}_k$ and
$\bm{\Pi}_{k+1}$
select the common rows in each epoch's state space; the implemented
state update is then
\begin{equation}
\smooth{\hat{\stateV}}{k}
  = \hat{\stateV}_{k|k}
    + \bm{\Pi}_k^{\Tr}\,\gainS_{k,C}
      \big(\bm{\Pi}_{k+1}\smooth{\hat{\stateV}}{k+1}
           - \bm{\Pi}_k\tilde{\stateV}_{k+1|k}\big),
\label{eq:rts-subspace}
\end{equation}
with the analogous projection on \Cref{eq:rts-cov}.  States outside the
subspace keep their forward a-posteriori value.  The indexing needs
care.  $\tilde{\stateV}_{k+1|k}$, $\tilde{\covM}_{k+1|k}$ and
$\Fmat_{k+1}$ are sized for epoch $k$'s layout, because the predict step
does not grow the state.  They are addressed with epoch $k$'s common
indices.  $\smooth{\hat{\stateV}}{k+1}$ and $\smooth{\covM}{k+1}$ use
epoch $k{+}1$'s layout.

\paragraph{Segment boundaries at resets and frame changes.}
Four mechanisms stop or restrict the backward flow of information at
ambiguity resets, teardowns, and pivot handovers:
\begin{itemize}[leftmargin=*, itemsep=0pt]
\item A \emph{complete} filter reset at $k{+}1$ (the covariance
      re-inflation of \Cref{sec:kf-gating}, recorded as
      \texttt{is\_discontinuity}) is a hard segment boundary.  It breaks
      the dynamic link $\tilde{\stateV}_{k+1|k} = \Fmat\hat{\stateV}_{k|k}$,
      so $\gainS_k$ has no meaning.  Backward flow stops and epoch $k$
      keeps its forward posterior.
\item A \emph{single-satellite} ambiguity reset is handled softly.  That
      satellite's ambiguities are excluded from the common subspace for
      the $k\!\to\!k{+}1$ step.  The re-seeded prior at $k{+}1$ has a
      large variance and carries no information backward, so smoothing
      it would only add noise.  The exclusion matches by satellite
      prefix and is slightly broader than necessary.  The extra states
      simply keep their forward values.
\item A \emph{dimension change}
      $\dim\tilde{\stateV}_{k+1|k} \neq \dim\hat{\stateV}_{k|k}$ is a hard
      boundary.  Predict never grows the state, so a size mismatch means
      a long-gap teardown before predict
      (\texttt{Application::handleGap} prunes ambiguity, iono and
      sat-bias states before \texttt{predict()}).  Across it, epoch $k$'s
      indices would address the wrong states in the $k{+}1$ a-priori.
      Backward flow stops and epoch $k$ keeps its forward posterior.
\item A \emph{BSSD pivot handover} between $k$ and $k{+}1$ re-references
      one or more constellations in place.  Each constellation is either
      reconciled or segmented, as described next.
\end{itemize}

\paragraph{BSSD pivot-handover reconciliation.}
When the pivot map changes between epochs
($\text{\texttt{pivot\_satellites}}_k \neq
\text{\texttt{pivot\_satellites}}_{k+1}$) the smoothed posterior at
$k{+}1$ is in the \emph{new} pivot frame.  The cached a-priori
$\tilde{\stateV}_{k+1|k}$ was captured before the handover, in epoch
$k$'s layout, and is still in the \emph{old} frame.  The two cannot be
compared directly in \Cref{eq:rts-state}.
\texttt{Smoother::prepareHandoverFrame} makes them comparable, per
constellation, on \emph{copies} of the $k{+}1$ smoothed estimate.  The
reported $k{+}1$ result stays in its own frame.  A handover that
\texttt{PivotManager} recorded as \emph{clean} (old and new pivots
matching \texttt{clean\_handovers}) is inverted back to the old pivot
$p_0$, one signal group at a time, by the public static
\texttt{Smoother::inverseReReferenceGroup}.  This is the exact inverse of
the forward re-reference.  For a group with old-pivot datum row $d$,
\begin{equation}
x'(i) = x(i) - x(d),\quad x'(d) = 0,
\qquad
P'(i,\cdot) = P(i,\cdot) - P(d,\cdot),\quad
P'(\cdot,j) = P(\cdot,j) - P(\cdot,d),
\label{eq:rts-handover}
\end{equation}
applied over \emph{full} rows and columns, with the datum row and column
set to zero last.  Full rows are needed because the forward re-reference
coupled the group to every other state.  A signal group can be inverted
only if the old pivot still has a live state on it \emph{and} the
forward step re-referenced that signal to the new pivot.  Everything
else is \emph{segmented}: orphaned groups (the new pivot lacked the
signal), disturbed or forced handovers, and the ionosphere and
satellite-bias states of every handover constellation.  Their keys are
added to the \texttt{exclude\_keys} set, which
\texttt{collectCommonIndices} removes from the common subspace, and
those states keep their forward posterior.

\paragraph{Static-position degeneracy.}
In static PPP the receiver position is nearly constant.  The smoother
gain for the position block then applies almost the same correction to
every epoch, and the smoothed position is constant across epochs
\emph{by construction}.  This is expected behaviour.  The smoother
improves the other states (troposphere, ionosphere, float ambiguities),
and the position in kinematic runs, where it really changes from epoch
to epoch.
