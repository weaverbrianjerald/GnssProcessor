% ============================================================
%  State vector layout
% ============================================================

The Kalman filter operates on a state vector $\stateV_k \in \mathbb{R}^{n_k}$
whose dimension $n_k$ varies across epochs.  A per-satellite or
per-(satellite, signal) state is appended when its satellite or signal is
first required, and removed when it is absent from the epoch's measurement
set (for example, after the satellite sets below the elevation mask).  A
cycle slip does not remove the ambiguity state; it re-seeds it (see the
ambiguity paragraph below).  \texttt{StateManager} holds all bookkeeping:
the key$\to$index maps, the appending of rows, and the compaction of
$\stateV$ and $\covM$ on removal, which shifts every later index down by
one (there is no free list).  \texttt{KalmanFilter} reads the state
through that interface and never indexes it by hard-coded offsets.  The
dynamic part of the vector is a set of families, each with one key$\to$index
map, declared once in a table (\Cref{sec:state-families}).

This section describes the single-receiver layout (PPP, PPP-RTK and the
baseline modes).  The network estimator keeps no \texttt{StateManager}: each
of its stations owns a parameter set of its own, described in
\Cref{sec:state-network}.

\subsection{Schematic layout}

In schematic form, suppressing the epoch index $k$:
\begin{align}
\stateV \;=\; \big[\,
& \underbrace{\rxpos_\rx^{\Tr}}_{3} \,,\,
  \underbrace{\bm{v}_\rx^{\Tr}}_{0\text{ or }3} \,,\,
  \underbrace{\sLight\,\mathrm{d}t_\rx}_{1} \,,\,
  \underbrace{(\sLight\,\delta t^{(g)}_\rx)_{g\neq g_{\mathrm{ref}}}^{\Tr}}_{|\sysset|-1} \,,\, \notag\\
& \underbrace{\zwd_\rx,\,(g_N, g_E)}_{1+0\text{ or }1+2} \,,\,
  \underbrace{(\sLight\,\mathrm{d}t^{\phi}_\rx)}_{0\text{ or }1} \,,\, \notag\\
& \underbrace{(I^\sat_{\rx,1})_{\sat \in \mathcal{V}_k}^{\Tr}}_{|\mathcal{V}_k|} \,,\,
  \underbrace{(N^\sat_{\rx,\sigl})_{(\sat,\sigl) \in \mathcal{A}_k}^{\Tr}}_{|\mathcal{A}_k|} \,,\, \notag\\
& \underbrace{(B_{\rx,\sigl})_{\sigl \in \sigset}^{\Tr}}_{|\sigset|} \,,\,
  \underbrace{(B^\sat_\sigl)_{(\sat,\sigl) \in \mathcal{D}_k}^{\Tr}}_{|\mathcal{D}_k|}
\,\big]^{\Tr}.
\end{align}
where
\begin{itemize}[leftmargin=*, itemsep=0pt]
\item $\mathcal{V}_k$ is the set of satellites visible at epoch $k$
      (above the elevation mask, with valid orbit and clock products and
      at least one tracked signal);
\item $\mathcal{A}_k \subseteq \mathcal{V}_k \times \sigset$ is the set
      of phase-tracked (satellite, signal) pairs;
\item $\mathcal{D}_k \subseteq \mathcal{V}_k \times \sigset$ is the
      subset of (satellite, signal) pairs that carry a satellite
      code-bias state: the pairs for which the BIA product lacks a
      satellite OSB (\texttt{estimation.estimate\_sat\_biases}).
\end{itemize}
The schematic omits several conditional refinements, detailed below: the
rate states that accompany velocity (a receiver clock rate and one
inter-system clock-rate offset per non-reference constellation, both
absent under BSSD); the optional per-satellite slant-ionosphere rate
under \texttt{enable\_iono\_rate}; the receiver inter-signal code biases;
the nine-state inertial augmentation of \dcref{sec:imu}{the inertial-aiding
document}; and the removal of the whole receiver-side clock and
inter-system-offset block under the BSSD parameterisation
(\Cref{sec:bssd}).

The schematic groups the states by physical role; it is not the storage
order.  \texttt{StateManager} places a fixed core first
(\texttt{StateManagerLayout.cpp}), in the order position, receiver clock
(absent under BSSD), ZWD, velocity, receiver clock rate, phase clock, the
two troposphere gradients, the nine inertial states, the inter-system time
offsets and the inter-system clock-rate offsets, each present only when
enabled.  Every dynamic state (ionosphere, ionosphere rate, ambiguity,
receiver code bias, satellite code bias) is appended after the core in
order of creation, so the categories interleave; each category is addressed
only through its key map, as described under dynamic indexing below.

\subsection{Component-by-component description}

\paragraph{Position $\rxpos_\rx \in \mathbb{R}^3$.}
ECEF Cartesian position of the antenna reference point.  Always present.
\texttt{Application::initializePosition} seeds it from the RINEX header
approximate position, shifted from the marker to the antenna reference
point by the header's antenna H/E/N offset (or from the Station
Information File coordinate when that a-priori source is enabled).  The
seed must lie within the linearisation radius of the geometric range
model (\Cref{sec:obs-geometry}).  The per-epoch Weighted Least-Squares
(WLS) solution seeds the receiver clock (on the first epoch, after a
clock jump and after a data gap); it re-seeds the position only in the
kinematic gap-recovery branch of \texttt{Application::handleGap}.

\paragraph{Velocity $\bm{v}_\rx \in \mathbb{R}^3$.}
Optional.  Enabled by \texttt{estimation.estimate\_velocity = true};
tightly-coupled IMU integration forces it on.  With velocity present,
position and velocity form a coupled continuous-white-noise-acceleration
(CWNA, integrated-random-walk) block driven by a single acceleration
spectral density, \texttt{process\_noise.acceleration\_psd\_q}
(\dcref{eq:kf-Q-cwna}{the CWNA process-noise model in the estimation
document}); the scalar \texttt{position\_q} of the velocity-free case is
then unused.  When BSSD is off, velocity estimation also adds a receiver
clock-rate state $\sLight\,\dot{\mathrm{d}t}_\rx$ and one inter-system
clock-rate offset (ISBR) per non-reference constellation, each
CWNA-coupled to its bias counterpart (\texttt{clock\_rate\_q},
\texttt{system\_time\_rate\_offset\_q}).  Under BSSD both rate states are
omitted, because same-system single differencing cancels them.

\paragraph{Receiver clock $\sLight\,\mathrm{d}t_\rx$.}
Single state, in metres.  Its process noise is large
(\texttt{clock\_bias\_q} $\sim 10^4\,\text{m}^2$ per second), so the
state is in effect re-estimated each epoch.  This follows oscillator
drift without imposing a stochastic model that may not match the
receiver's oscillator.  Under the BSSD (between-satellite
single-difference) parameterisation (\Cref{sec:bssd}) the receiver clock
is unobservable and the state is not allocated; neither are the
inter-system offsets below, so PPP-RTK SD mode has no receiver-side clock
block.

\paragraph{Inter-system time offsets $\sLight\,\delta t^{(g)}_\rx$.}
One per active constellation other than GPS, which is the fixed
reference in \texttt{StateManager}.  These absorb the per-constellation
clock biases that arise from mixing analysis-centre clock products across
systems (``GAL\,$-$\,GPS time offset,'' etc.).

\paragraph{Tropospheric ZWD and gradients.}
$\zwd_\rx$ is the zenith wet delay.  The zenith hydrostatic delay
$\zhd_\rx$ is deterministic, from the Saastamoinen model
\cite{saastamoinen1972atmospheric}.  The total slant tropospheric delay
is
\begin{equation}
T^\sat_\rx \;=\;
m_h(\theta^\sat_\rx)\,\zhd_\rx
\;+\;
m_w(\theta^\sat_\rx)\,\zwd_\rx
\;+\;
m_g(\theta^\sat_\rx) \big[
g_N \cos\alpha^\sat_\rx + g_E \sin\alpha^\sat_\rx
\big],
\label{eq:tropo-mapping}
\end{equation}
with elevation $\theta^\sat_\rx$, azimuth $\alpha^\sat_\rx$, the mapping
functions $m_h, m_w$ (the Niell tables by default, labelled \texttt{Gmf}
in the configuration, or VMF3 with GPT3 coefficients when configured) and
the Chen--Herring gradient mapping
$m_g(\theta) = 1/(\sin\theta\tan\theta + 0.0032)$
\cite{chen1997effects}
(\dcref{sec:atmos}{the atmosphere document}).  The gradients $(g_N, g_E)$
are optional.

\paragraph{Per-satellite slant ionosphere $I^\sat_{\rx,1}$.}
Uncombined processing in every mode except the baseline modes
(\texttt{processing.uncombined\_enabled}, forced on for the PPP-RTK family;
\texttt{GnssConfig::carriesSlantIonosphere}).  One state per visible
satellite, expressed at the L1 frequency; signal-specific delays follow
\Cref{eq:iono-scaling}.  The seed is formed from the geometry-free
combination of the satellite's BIA-covered code residuals
(\texttt{seedIonosphere}, \dcref{sec:estinfra-init}{the first-epoch seeding section of the estimator-infrastructure document}).  With fewer than two
covered codes on different bands, the seed is zero and the initial standard
deviation is inflated tenfold.  The initial variance, like the process noise,
is scaled by the obliquity factor.  The process noise is a random walk
whose zenith spectral density \texttt{ionosphere\_q} is projected onto the
slant by the squared obliquity factor $1/\sin^2\theta^\sat_\rx$
(\dcref{eq:kf-Q-iono}{the ionospheric process-noise model in the
estimation document}), so low-elevation states vary faster.  It is applied
on every run that carries the states, in PPP as in PPP-RTK; without it the
state would be a constant that cannot follow a slant delay moving by metres
per pass.  These
explicit per-satellite states let PPP-RTK keep integer ambiguity recovery
without forming the ionosphere-free combination, which amplifies code
noise by a factor of $\sim 3$.  Under \texttt{estimation.enable\_iono\_rate}
(default off), each visible satellite also carries a slant-ionosphere
rate, so that the pair forms a constant-velocity block
$[\,I^\sat_{\rx,1},\,\dot I^\sat_{\rx,1}\,]$.  The rate
$\dot I^\sat_{\rx,1}$ has no direct observation ($H=0$); only the
$F$-coupling into the level state drives it.  It has its own spectral
density \texttt{process\_noise.iono\_rate\_psd} and its own slip response
(\texttt{reinflateIonosphereRateVariance}), and lets the filter track a
linear slant ramp rather than a pure random walk.  The rate state is a
satellite-specific dynamic row, not a core state: it is appended with its
level state, pruned with it and treated with the other per-satellite
states in gap recovery, but after prunes and re-adds it need not sit next
to the level state, so it is addressed only through its own map
(\texttt{iono\_rate\_indices\_}).

\paragraph{Carrier-phase ambiguities $N^\sat_{\rx,\sigl}$.}
One state per phase-tracked $(\sat, \sigl)$ pair, in metres (the state
value is $\lambda N$; the \texttt{nl\_wl} basis below is the exception,
carrying integers in cycles).  The ambiguities are float through the
prediction and update cycle; when AR is enabled, the LAMBDA-family
algorithms in \texttt{filter/AmbiguityResolver}
\cite{teunissen1995lambda} resolve them to integers afterwards.  A cycle
slip calls \texttt{StateManager::resetAmbiguity}, which decorrelates the
state rather than repairing it: the ambiguity's covariance row and column
are zeroed, its diagonal is reset to $\sigma_m^2$, and the key is marked
pending re-seed.  The state value is left unchanged by the reset;
\texttt{ensureRequiredStates} (in \texttt{MeasurementModel}) then overwrites it with a
geometry-based seed (\texttt{seedAmbiguity}, \dcref{sec:estinfra-init}{the first-epoch seeding section of the estimator-infrastructure document}).
This is the project's reset-over-repair convention:
a slipped ambiguity has no trustworthy correlation with the rest of the
state, so its cross-covariances are cleared.  A reset for a key that is
not in the state (for example, a signal excluded by the band filter) is
refused and creates no state.

\paragraph{Receiver code biases $B_{\rx,\sigl}$.}
These absorb the receiver-side inter-frequency biases that the OSB
convention does not reference to zero.  They are not one per signal.
The receiver-bias rule (\texttt{ReceiverBiasResolver::resolveReceiverBias},
\texttt{measurement/ReceiverBias.hpp}) keys them per (system,
frequency band): both bands of the system's clock-reference signal pair
map to one per-system differential code bias (\texttt{"<system>\_DCB"}),
each band with its own coefficient, and every other band gets its own
inter-frequency bias (\texttt{"<system>\_IFB<band>"}).  Like the receiver
clock they are receiver-common, so under BSSD they receive no process
noise and the SD transform zeroes their columns.  The same rule serves the
network estimator, whose stations additionally give a second code of a
band, one that is not the station's latched canonical code on that band, a
receiver inter-signal code bias (\texttt{"<system>\_ISC\_<signal>"}, unit
coefficient, GLONASS excluded; \texttt{network.second\_code\_channel} or
\texttt{processing.channel\_mode: all}).  The network treatment, with its
carry, is in \Cref{sec:state-network}.

\paragraph{Per-slot GLONASS inter-frequency bias $B^{(g,b)}_{\rx,k}$.}
Optional, off by default.  GLONASS FDMA assigns each slot $k\in[-7,+6]$
a distinct carrier frequency $f = f_{\mathrm{base}} + k\,\Delta f$, so
the receiver group delay differs per slot and a single per-band IFB state
cannot represent it.  With \texttt{estimation.glonass\_ifb.enable = true}
and its prerequisite \texttt{estimation.estimate\_ifb} (without which the
loader warns and the flag is inert), the receiver-bias rule instead
creates one state per (FDMA band $b\in\{$G1,\,G2$\}$, slot $k$) with
unit measurement coefficient, keyed
\texttt{"GLONASS\_IFB<band>\_k<$\pm$slot>"}.  The central channel $k=0$
is the held datum and has no state; the GLONASS inter-system time offset
absorbs its constant.  The CDMA bands (G3/G4/G6) have a slot-independent
frequency; with the flag on, the GLONASS branch of the rule
returns no receiver bias key for them (it
handles every GLONASS signal and does not fall through to the per-band
path).  With the flag off, GLONASS carries no per-band IFB state on a
non-reference band.  Unlike the receiver-common biases, these columns
survive between-satellite single differencing, because two GLONASS
satellites on different slots do not cancel.  \texttt{BssdTransform} and
\texttt{StateManager} therefore exempt them from the receiver-block
zeroing and from the process-noise suppression (via
\texttt{isGlonassPerSlotIfbKey}); only the inter-slot differences are
estimable in SD.

\paragraph{Satellite code biases $B^\sat_\sigl$.}
Per (satellite, signal) pair, but only for a pair whose OSB the BIA file
does not supply, typically a third-frequency signal in a triple-frequency
setup (\texttt{estimation.estimate\_sat\_biases}).  The network estimator
estimates its own satellite code biases as parameters instead, covering every
raw code and not using the external \texttt{.BIA} (\Cref{sec:state-network}).
These states are weakly stochastic (\texttt{sat\_bias\_q} $\sim 10^{-10}$),
because the underlying physical biases are nearly stationary over a day.

\paragraph{Inertial augmentation.}
With IMU integration enabled, the core state gains nine entries: a
three-axis attitude error and the three-axis accelerometer and gyroscope
biases.  The strapdown mechanisation propagates them, rather than the
random-walk process model.  \dcref{sec:imu}{The inertial-aiding document}
treats them in full.

\paragraph{Baseline differential troposphere.}
In baseline mode the core is the position alone; double differencing
cancels the receiver clocks and inter-system offsets, and on a short
baseline the ionosphere and troposphere, so none of those states exists.
An optional single differential zenith-wet-delay state
$\Delta\zwd_{\rx_{\mathrm{rov}}\rx_{\mathrm{ref}}}$ follows the position
(\texttt{baseline.estimate\_differential\_tropo}, \Cref{sec:dd}).  This is
the only mode in which \texttt{StateManager} reads its
\texttt{core\_state\_size} constructor argument; the PPP and PPP-RTK paths
ignore it and derive the core layout from the configuration.

\subsection{Declared state families}\label{sec:state-families}

The dynamic families are declared once, in \texttt{include/filter/StateFamily.hpp}
(\texttt{kStateFamilies}).  Each row gives the family's label prefix and
snapshot tag, the variance re-inflation it answers to, its gap response, the
rule that names the satellite of a key (a state whose satellite is a frozen
pivot gets no process noise), its process-noise rule and spectral-density
key, the configuration that enables its birth and the source of its initial
variance.  Every place that visits all families (the state size, the index
shift on removal, the state labels, the real-time snapshot) reads the table.
\Cref{tab:state-families} lists the rows.  At run start
\texttt{StateManager::logFamiliesAsArmed} prints one line per family: whether
the configuration births it, the label and tag, the initial standard
deviation with its source, the process-noise rule with its value and the
events wired to it (re-inflation, reset, prune, gap decoupling, the
frozen-pivot skip, the snapshot).  A family that is born and has no process
noise reads \texttt{Q none} in that line.

\subsection{Dynamic indexing}\label{sec:state-indexing}

\texttt{StateManager} addresses the variable-dimension blocks through
key$\to$index maps.  \texttt{include/filter/StateKeySchema.hpp} defines
every key format once, each with a \texttt{make} builder and, for the
categories that are read back, a \texttt{parse} helper (the ionosphere
and inter-system time-offset keys have no parser, since the key is the
bare satellite or system name).  Some call sites still build keys by
string concatenation rather than through the builders (for example the
double-difference keys in \texttt{MeasurementModel},
\texttt{DdPivotManager} and \texttt{KalmanFilter}); the strings they
produce match the schema formats.  The one function that renders a typed
parameter identity as a user-side key is \texttt{userKey}
(\texttt{measurement/UserParamView.hpp}).  The formats are:
\begin{itemize}[leftmargin=*, itemsep=0pt]
\item iono key: \texttt{"<sys><prn>"}, e.g.\ \texttt{"G05"} (delimiter-free);
\item ambiguity key: \texttt{"<sys><prn>\_<signal>"}, e.g.\ \texttt{"G05\_L1C"},
      split on the \emph{first} underscore, so an iono-free combination
      \texttt{"G05\_L1C\_L5Q"} retains its compound signal;
\item satellite signal-bias key (code): \texttt{"<sys><prn>|<signal>"},
      e.g.\ \texttt{"G05|C1W"}, with a pipe delimiter and its own map,
      disjoint from the underscore ambiguity namespace;
\item satellite phase-bias key (network): \texttt{"<sys><prn>|<signal>|PB"},
      e.g.\ \texttt{"G05|L1C|PB"}, where the trailing \texttt{|PB} keeps it
      disjoint from the code-bias namespace;
\item receiver phase-bias key (network): \texttt{"<system>\_RPB\_<signal>"},
      e.g.\ \texttt{"Galileo\_RPB\_L5Q"}, where the \texttt{\_RPB\_} infix keeps
      it disjoint from the receiver code-bias namespace (which matches on
      \texttt{IFB}/\texttt{DCB});
\item satellite clock key (network): \texttt{"<sat>|SC"}, e.g.\
      \texttt{"G05|SC"}, per satellite rather than per signal; the trailing
      \texttt{|SC} discriminator gives the clock its own namespace;
\item receiver code-bias key: \texttt{"<system>\_IFB<band>"} or
      \texttt{"<system>\_DCB"}; the per-slot GLONASS variant appends an
      FCN marker, \texttt{"GLONASS\_IFB<band>\_k<$\pm$slot>"} (e.g.\
      \texttt{"GLONASS\_IFB1\_k-4"});
\item receiver inter-signal code-bias key (network):
      \texttt{"<system>\_ISC\_<signal>"}, e.g.\ \texttt{"GPS\_ISC\_C1W"}, stored
      in the receiver code-bias map; the \texttt{\_ISC\_} infix matches neither
      the IFB nor the DCB parser;
\item inter-system time-offset key: the bare system name
      (\texttt{"Galileo"}, \dots; GPS is the reference and never appears);
\item double-difference ambiguity key (baseline):
      \texttt{"DD|<cons>|<sat>|<code>|<pivot>"}.
\end{itemize}
Addressing states by key rather than by position removes the index
bookkeeping errors of hand-managed dynamic state vectors, and lets the
BSSD and DD S-transforms (\Cref{sec:diff}) operate as block operations on
the relevant key sets.

Two further categories in the schema header are absent from the list
above, because they are not rows of $\stateV$.  The first is the BSSD
pivot absolute-seed lookup key (\texttt{"<cons>|<band>"}).  Its builder
has no production caller and it has no parser: \texttt{MeasurementModel}
builds the \texttt{pivot\_abs\_seeds} keys by concatenation, with the full
phase signal code in place of the band (\texttt{"GPS|L1C"}), plus
narrow-lane and wide-lane variants under the \texttt{nl\_wl} basis.  The
second is the spherical-harmonic VTEC coefficient key
(\texttt{"SH|<n>|<m>|<C|S>"}, with the second shell on the distinct
\texttt{SH2} prefix), which names a column of the network's shared border,
not a \texttt{StateManager} state, and has a \texttt{make}/\texttt{parse}
pair.  It belongs to the optional co-estimated map that the reference
configurations do not use.  Both appear in
\dcref{tab:gen-state-keys}{the generated key-format table of the appendix},
which is derived from the schema header by a script and is therefore the
completeness reference for the list above.

\paragraph{Ambiguity basis.}
By default the ambiguity block carries one per-band float ambiguity per
tracked (satellite, signal), in metres.  Setting
\texttt{estimation.state\_ambiguity\_basis = "nl\_wl"} switches the
whole run to a narrow-lane\,/\,wide-lane parameterisation.  Each satellite
has a reference band, the lowest-numbered band it is observed on that
epoch, and carries one narrow-lane state tied to that band (key
\texttt{"<sat>\_NL\_<band>"}) and one wide-lane state for each other
observed band, paired with the reference band
(\texttt{"<sat>\_WL\_<a>\_<b>"}, with the band digits in ascending order,
semantically $N_a - N_b$).  A change of reference band produces new keys,
and the old states are pruned.  Both kinds are in cycles rather than
metres, so the wide-lane and \textsc{lambda} arithmetic stays native to
integers; the Jacobian carries the wavelength scaling
(\Cref{tab:obs-terms}).  The two bases never coexist in a single state
vector.  The network estimator does not use this basis.

\subsection{Network station parameters}\label{sec:state-network}

The network estimator runs no \texttt{KalmanFilter} and keeps no
\texttt{StateManager}.  Each station owns a parameter set
(\texttt{StationParams}, \texttt{network/state/StationParams.hpp}): its
columns in column order, each with a typed identity (kind, form, satellite,
signal), the linearisation point the epoch's rows are evaluated at, and the
disposition the station split gave it.  The set is the station's own state
and the network its only writer.  A station's layout holds the receiver
position (held at the roster coordinate and never estimated), the receiver
clock, the zenith wet delay and one inter-system bias per active
non-reference constellation.  The families born during the run are the
per-satellite slant ionosphere, the ambiguities (always one per band), the
receiver code biases and, when armed, the phase colour.  The set also names
the shared satellite parameters the station's rows reference: the satellite
clock correction and the satellite phase and code biases.  The optional
columns of the single-receiver filter (velocity, clock rate, phase clock,
gradients, inertial states, NL/WL ambiguities, between-satellite
differencing) are not part of it, and a network run that enables one is
warned at start.  The rows of a station are built from the set by the
shared observation equation (\Cref{sec:obs-shared}); the births of the
local families and their first-epoch seeds are in
\texttt{network/assembly/LocalBirth.cpp} (\dcref{sec:estinfra-init}{the first-epoch seeding section of the estimator-infrastructure document}).

\paragraph{Parameters as armed.}
The network declares each kind of parameter once
(\texttt{network/assembly/ParamRegistry.hpp}) and prints a table at run
start, \texttt{network/assembly/ParamInventory.hpp}, that counts every class of
parameter (kind, constellation, signal or band) by what the network did
with each instance on the epoch: estimated in the shared border, estimated
in the station's local block, held at its seed outside the solve, absorbed
(a shared parameter that a gate withheld from the station, another column
taking it up), pinned (the station coordinates), dropped, or unobserved.  A
declared rule whose premise does not hold on the run is printed as a warning
under the table.

\paragraph{Time linking.}
The estimator solves the normal equations of an epoch.  It links epochs
with explicit carried priors in information form, of effective variance
$\mathrm{var}_{\mathrm{eff}} = \mathrm{var} + q\,\dt$, not through a
$\Qmat(\dt)$ (\dcref{sec:net}{the network-mode document}).  The satellite-side
densities \texttt{sat\_clock\_q}, \texttt{sat\_phase\_bias\_q} and
\texttt{sat\_code\_bias\_q} are read as those carry rates.  They can be set
through the legacy \texttt{filter.process\_noise.*} keys or through the
network-scoped \texttt{network.process\_noise} class table, whose per-class
fallbacks equal the legacy defaults.

\paragraph{Satellite clocks $\sLight\,\Delta\delta t^\sat$.}
Gated by \texttt{estimation.estimate\_sat\_clocks}, which the
network-estimator loader forces on together with the phase-bias flag
(\texttt{GnssConfigLoadNetwork.cpp}, the line that logs
\emph{forcing estimate\_sat\_clocks + estimate\_sat\_phase\_biases}) and
which \texttt{GnssConfig::applyNetworkConsumerCouplings} turns off again for
the closed-loop user, who takes the same quantity as a known correction.  The
network estimates an explicit per-satellite clock correction
$\Delta\delta t^\sat$ (in metres, relative to the a-priori precise or
real-time product clock already removed from the modelled value), so
the emitted clocks stay consistent with the chosen S-system datum.  There
is one parameter per satellite, shared by all its signals.  The satellite orbit
stays fixed from the product; only the clock is estimated.  It enters each
row with the partial $-1$ (\Cref{sec:obs-shared}); its identity is spelled
\texttt{"<sat>|SC"}.

\paragraph{Satellite phase biases $\bar b^\sat_\sigl$.}
Gated by \texttt{estimation.estimate\_sat\_phase\_biases}; the JSON
default is off and the network-estimator loader forces it on, as above.  The
user side imports the satellite phase bias as a known SSR correction
(\dcref{sec:ssr}{the SSR-corrections document}) or absorbs it into the float
ambiguity.  The network instead carries an explicit per-(satellite, signal)
phase-bias parameter on the undifferenced phase rows: the estimable bias of
\textcite{odijk2003fast}, which lumps the network pivot-receiver ambiguity.
On a single station's row it is collinear with the per-receiver float
ambiguity; only the joint network estimator separates it, across stations
(\dcref{sec:net-phasebias}{the explicit phase-bias section of the
network-mode document}).  Its identity is spelled \texttt{"<sat>|<signal>|PB"},
disjoint from the code-bias namespace.  It is near-stationary between epochs,
with the carry rate \texttt{sat\_phase\_bias\_q}.

\paragraph{Satellite code biases.}
In the network's satellite-OSB mode (\texttt{network.estimate\_sat\_code\_bias},
armed in the reference configurations) the parameter set covers every raw code
$(\sat,\sigl)$, not only the pairs the BIA file leaves uncovered, and the
external \texttt{.BIA} is not used, so the network's own estimate is the
single code-bias source.  The datum that makes it estimable is derived in
\dcref{sec:net}{the network-mode document}.  The carry rate is
\texttt{sat\_code\_bias\_q}.

\paragraph{Receiver code biases and inter-signal biases.}
The receiver code-bias rule is the one of the single-receiver filter
(above).  On the network, a code that is not the station's latched canonical
code on its band gets the separate receiver inter-signal code bias.  These
columns have no Kalman time update, because the network runs no
\texttt{KalmanFilter}; they are re-estimated each epoch unless
\texttt{network.carry\_rx\_code\_bias} is armed (loader default off; armed in
the reference configurations).  That setting adds a diagonal random-walk
carry ($\mathrm{var} + q\,\dt$) held in the network run state.  Two guards
protect it: at load, the loader forces the carry off unless the code datum is
time-linked (\texttt{network.code\_datum\_time\_linked}); at inject time, an
innovation gate (\texttt{rxCbInjectGate}, \texttt{network/driver/RunTypes.hpp})
withholds the fold when the carried level and the station's own estimate
disagree at receiver-reset scale.  With the satellite code biases estimated,
the receiver inter-frequency biases of the bands outside a constellation's
clock-reference pair stay in the set at the value their first-epoch seed gave
them and are left out of the station's local block, unless
\texttt{network.estimate\_rx\_extra\_band\_code\_delay} is armed
(\dcref{sec:net-constellations}{the constellation-scope section of the
network-mode document}).

\paragraph{Receiver phase biases $\delta_{\rx,\sigl}$.}
The receiver-side counterpart of the satellite phase bias, gated by
\texttt{network.phase\_datum\_eq34} (the single-receiver-chain phase datum;
see \dcref{sec:net}{the network-mode document}).  The setting is off in the
reference configurations, which use the held phase-datum basis of the float
vehicle (\dcref{sec:net-vehicle}{the float-vehicle document}).  When armed,
each $\delta_{\rx,\sigl}$ is an estimable parameter, so the receiver
fractional phase bias no longer lumps into the emitted satellite phase bias.
It is per (receiver, system, signal), spelled \texttt{"<system>\_RPB\_<signal>"}.
Unlike every other bias parameter described here, these are local, each
observed by a single station.  At \texttt{network.phase\_datum\_eq34\_rpb\_q\_m2s}
$=0$ each $\delta_{\rx,\sigl}$ is re-estimated every epoch; at the non-zero
default (\SI{3e-6}{\metre\squared\per\second}) a local time-linking prior
toward the previous estimate, of variance $\mathrm{var} + q\,\dt$, suppresses
the per-epoch bounce that a weakly observable local parameter otherwise injects,
anti-correlated, into every individual float ambiguity.  The prior is erased
for any $(\sat,\sigl)$ whose chain frame stepped at that epoch's election
(\texttt{network/solve/ChainDatum.hpp}).

\paragraph{Phase colour.}
With \texttt{network.phase\_colour\_state} a per-satellite nuisance state with
the partial $+1$ on every phase row of the satellite is born at value zero;
it is off in the reference configurations.
