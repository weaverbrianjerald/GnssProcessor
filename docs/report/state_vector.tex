% ============================================================
%  State vector layout
% ============================================================

The Kalman filter operates on a state vector $\stateV_k \in \mathbb{R}^{n_k}$
whose dimension $n_k$ \emph{varies across epochs}: per-satellite and
per-(satellite, signal) substates are added when a new sat/signal is
first observed and pruned (or marked stale) when the satellite drops
below the elevation mask or its phase track is interrupted by a cycle
slip without recovery.  All bookkeeping --- key$\to$index maps, free-list
re-use, and dimensional reshaping of $\stateV$ and $\covM$ --- is
encapsulated in \texttt{StateManager}; \texttt{KalmanFilter} consumes
the state through that interface and never indexes raw memory by
hard-coded offsets.

\subsection{Schematic layout}

In schematic form, suppressing the epoch index $k$:
\begin{align}
\stateV \;=\; \big[\,
& \underbrace{\rxpos_\rx^{\Tr}}_{3} \,,\,
  \underbrace{\bm{v}_\rx^{\Tr}}_{0\text{ or }3} \,,\,
  \underbrace{\sLight\,\mathrm{d}t_\rx}_{1} \,,\,
  \underbrace{(\sLight\,\delta t^{(g)}_\rx)_{g\neq g_{\mathrm{ref}}}^{\Tr}}_{|\sysset|-1} \,,\, \notag\\
& \underbrace{\zwd_\rx,\,(g_N, g_E)}_{1+0\text{ or }1+2} \,,\,
  \underbrace{(\sLight\,\mathrm{d}t^{\phi}_\rx)}_{0\text{ or }1} \,,\, \notag\\
& \underbrace{(I^\sat_{\rx,1})_{\sat \in \mathcal{V}_k}^{\Tr}}_{|\mathcal{V}_k|} \,,\,
  \underbrace{(N^\sat_{\rx,\sigl})_{(\sat,\sigl) \in \mathcal{A}_k}^{\Tr}}_{|\mathcal{A}_k|} \,,\, \notag\\
& \underbrace{(B_{\rx,\sigl})_{\sigl \in \sigset}^{\Tr}}_{|\sigset|} \,,\,
  \underbrace{(B^\sat_\sigl)_{(\sat,\sigl) \in \mathcal{D}_k}^{\Tr}}_{|\mathcal{D}_k|}
\,\big]^{\Tr}.
\end{align}
where
\begin{itemize}[leftmargin=*, itemsep=0pt]
\item $\mathcal{V}_k$ is the set of satellites currently visible at
      epoch $k$ (i.e.\ above the elevation mask, with valid orbit/clock
      products and at least one tracked signal),
\item $\mathcal{A}_k \subseteq \mathcal{V}_k \times \sigset$ is the set
      of phase-tracked (satellite, signal) pairs,
\item $\mathcal{D}_k \subseteq \mathcal{V}_k \times \sigset$ is the
      subset of (satellite, signal) pairs carrying a satellite
      code-bias state: the pairs for which the BIA product lacks a
      satellite OSB or --- under the network producer's satellite-OSB
      mode --- every raw code pair (see
      \texttt{estimation.estimate\_sat\_biases} and
      \texttt{network.estimate\_sat\_code\_bias}).
\end{itemize}
For brevity the schematic suppresses several conditional refinements
detailed below: the rate states that accompany velocity (a receiver
clock-rate and one inter-system clock-rate offset per non-reference
constellation), the optional per-satellite slant-iono \emph{rate}
companion under \texttt{enable\_iono\_rate}, the network-producer
satellite-clock and receiver-phase-bias states, the nine-state inertial
augmentation of \dcref{sec:imu}{the inertial-aiding document},
and the fact that the entire receiver-side clock and inter-system-offset
block is removed under the BSSD parameterisation (\Cref{sec:bssd}).

\subsection{Component-by-component description}

\paragraph{Position $\rxpos_\rx \in \mathbb{R}^3$.}
ECEF Cartesian receiver position.  Always present.  Initialised either
from the RINEX header approximate position or, after the first epoch,
from a Weighted Least-Squares (WLS) seed solution to within the
linearisation radius of the geometric range model
(\Cref{sec:obs-geometry}).

\paragraph{Velocity $\bm{v}_\rx \in \mathbb{R}^3$.}
Optional.  Enabled by \texttt{estimation.estimate\_velocity = true}, or
forced on by tightly-coupled IMU integration.  When present, position
and velocity form a coupled continuous-white-noise-acceleration (CWNA,
integrated-random-walk) block driven by a \emph{single} acceleration
spectral density \texttt{process\_noise.acceleration\_psd\_q}
(\dcref{eq:kf-Q-cwna}{the CWNA process-noise model in the estimation
document}); the scalar \texttt{position\_q} of the
velocity-free case is then unused.  Enabling velocity also introduces a
receiver clock-rate state $\sLight\,\dot{\mathrm{d}t}_\rx$, and one
inter-system clock-rate offset per non-reference constellation, each
CWNA-coupled to its bias counterpart (\texttt{clock\_rate\_q},
\texttt{system\_time\_rate\_offset\_q}).

\paragraph{Receiver clock $\sLight\,\mathrm{d}t_\rx$.}
Single state, in metres.  Process noise is large
(\texttt{clock\_bias\_q} $\sim 10^4\,\text{m}^2$ per second) so the
state is effectively re-estimated each epoch; this captures
oscillator drift without imposing a stochastic model that may not
match the receiver's actual oscillator.  Under the BSSD
(between-satellite single-difference) parameterisation
(\Cref{sec:bssd}) the receiver clock is unobservable and the state is
dropped entirely --- as are the inter-system offsets below --- so the
whole receiver-side clock block vanishes in PPP-RTK SD mode.

\paragraph{Inter-system time offsets $\sLight\,\delta t^{(g)}_\rx$.}
One per active constellation other than the chosen reference (default
GPS).  These absorb the per-constellation clock biases that arise from
mixing analysis-centre-defined clock products across systems
(``GAL\,$-$\,GPS time offset,'' etc.).

\paragraph{Tropospheric ZWD and gradients.}
$\zwd_\rx$ models the zenith wet delay; the zenith hydrostatic
component $\zhd_\rx$ is treated deterministically via the Saastamoinen
model \cite{saastamoinen1972atmospheric}.  Total slant tropospheric
delay is then
\begin{equation}
T^\sat_\rx \;=\;
m_h(\theta^\sat_\rx)\,\zhd_\rx
\;+\;
m_w(\theta^\sat_\rx)\,\zwd_\rx
\;+\;
m_w(\theta^\sat_\rx)\cot\theta^\sat_\rx \big[
g_N \cos\alpha^\sat_\rx + g_E \sin\alpha^\sat_\rx
\big],
\label{eq:tropo-mapping}
\end{equation}
with elevation $\theta^\sat_\rx$, azimuth $\alpha^\sat_\rx$, and the
Niell or VMF mapping functions $m_h, m_w$.  Gradients $(g_N, g_E)$ are
optional.

\paragraph{Per-satellite slant ionosphere $I^\sat_{\rx,1}$.}
PPP-RTK-only.  One state per visible satellite, expressed at the L1
frequency; signal-specific delays follow \Cref{eq:iono-scaling}.
Initial value seeded from the Klobuchar broadcast model when no
external ionospheric product is available.  Its process noise is a
random walk whose zenith spectral density \texttt{ionosphere\_q} is
projected onto the slant by the squared obliquity factor
$1/\sin^2\theta^\sat_\rx$ (\dcref{eq:kf-Q-iono}{the ionospheric
process-noise model in the estimation document}), letting low-elevation
states vary faster.  Modelling these per-sat states explicitly is what
permits PPP-RTK to retain integer ambiguity recovery without forming
the ionosphere-free combination (which amplifies code noise by a factor
of $\sim 3$).  Optionally, under \texttt{estimation.enable\_iono\_rate}
(default off), each visible satellite carries a companion
constant-velocity block $[\,I^\sat_{\rx,1},\,\dot I^\sat_{\rx,1}\,]$: the
slant-iono \emph{rate} $\dot I^\sat_{\rx,1}$ is unobserved directly
($H=0$) and driven only by the $F$-coupling into the level state, with
its own spectral density \texttt{process\_noise.iono\_rate\_psd} and its
own slip response (\texttt{reinflateIonosphereRateVariance}), letting the
filter track a linear slant ramp rather than a pure random walk.

\paragraph{Carrier-phase ambiguities $N^\sat_{\rx,\sigl}$.}
One state per phase-tracked $(\sat, \sigl)$ pair, in metres (the state
value is $\lambda N$; the \texttt{nl\_wl} basis below is the exception,
carrying integers in cycles).  Treated
as float during the prediction/update cycle and resolved to integers
post-hoc by the LAMBDA-family algorithms in
\texttt{filter/AmbiguityResolver} \cite{teunissen1995lambda} when AR
is enabled.  Cycle slips trigger a re-seed via
\texttt{StateManager::resetAmbiguity}, which \emph{decorrelates} the
state rather than repairing it: the ambiguity's covariance row and column
are zeroed and its diagonal reset to $\sigma_m^2$, while the state
\emph{value} is left unchanged (it is overwritten by the geometry-based
seed in \texttt{ensureRequiredStates}).  This follows the project's
reset-not-repair convention --- a slipped ambiguity carries no
trustworthy correlation to the rest of the state, so the cross-state
correlations are broken, not preserved.

\paragraph{Receiver code biases $B_{\rx,\sigl}$.}
These absorb the receiver-side inter-frequency biases that the OSB
convention does not reference to zero.  They are \emph{not} one per
signal: \texttt{StateInitializer::resolveReceiverBias} keys them per
(system, frequency band) as inter-frequency biases
(\texttt{"<system>\_IFB<band>"}) plus, in the alternative scheme, a
single per-system differential code bias (\texttt{"<system>\_DCB"}).
Like the receiver clock they are receiver-common and so are suppressed
under BSSD.  On the network path these columns have no Kalman time update
at all --- the producer runs no \texttt{KalmanFilter}
(\dcref{sec:kf}{the filtering document}) --- so they are re-estimated
afresh each epoch unless \texttt{network.carry\_rx\_code\_bias} is armed:
an opt-in, default-off diagonal random-walk carry
($\mathrm{var} + q\,\dt$) held in the network run context rather than in
\texttt{StateManager}, guarded at load by the requirement of a time-linked
code datum (\texttt{network.code\_datum\_time\_linked}, absent which the
loader forces the carry off) and at inject time by an innovation gate
(\texttt{rxCbInjectGate} in \texttt{filter/NetworkRunTypes}) that withholds
the fold when the carried level and the station's own estimate disagree at
receiver-reset scale.  It is not yet field-validated.

\paragraph{Per-slot GLONASS inter-frequency bias $B^{(g,b)}_{\rx,k}$.}
Optional, off by default.  GLONASS FDMA assigns each slot $k\in[-7,+6]$
a distinct carrier frequency $f = f_{\mathrm{base}} + k\,\Delta f$, so
the receiver group delay differs \emph{per slot} and a single per-band
IFB state cannot represent it.  When
\texttt{estimation.glonass\_ifb.enable = true} (and the prerequisite
\texttt{estimation.estimate\_ifb}; the loader warns and the flag is inert
otherwise), \texttt{resolveReceiverBias} instead emits one state per
(FDMA band $b\in\{$G1,\,G2$\}$, slot $k$) with unit measurement
coefficient, keyed \texttt{"GLONASS\_IFB<band>\_k<$\pm$slot>"}.  The
central channel $k=0$ is the held datum and produces no state; its
constant is absorbed by the GLONASS inter-system time offset.  CDMA
bands (G3/G4/G6) have a slot-independent frequency and retain the
ordinary per-band treatment above.  Crucially, unlike the
receiver-common biases these columns \emph{survive} between-satellite
single differencing --- two GLONASS satellites on different slots do not
cancel --- so \texttt{BssdTransform} and \texttt{StateManager}
special-case them (via \texttt{isGlonassPerSlotIfbKey}) to exempt them
from the receiver-block zeroing; only the inter-slot \emph{differences}
remain estimable in SD.

\paragraph{Satellite code biases $B^\sat_\sigl$.}
Per (satellite, signal) pair, but \emph{only when the BIA file does
not supply an OSB} for that pair --- typically a third-frequency
signal in a triple-frequency setup.  That fallback rule is the user-path
and network-V1 behaviour.  Under the network producer's satellite-OSB mode
(\texttt{network.estimate\_sat\_code\_bias}, also implied and forced on by
\texttt{network.estimate\_iono\_sh}) the loader instead \emph{promotes} the
state to every raw code $(\sat,\sigl)$ rather than only the uncovered
pairs, and suppresses the external \texttt{.BIA} entirely so the network's
own estimate is the single code-bias source; the datum that makes it
estimable is derived in \dcref{sec:net}{the network-mode document}.
When present, these states are
weakly stochastic (\texttt{sat\_bias\_q} $\sim 10^{-10}$) since the
underlying physical biases are nearly stationary on the daily
timescale.

\paragraph{Satellite phase biases $\bar b^\sat_\sigl$ (network mode).}
Present only in the network producer
(\texttt{ProcessingMode::PPP\_RTK\_Network}) and gated by
\texttt{estimation.estimate\_sat\_phase\_biases}.  The JSON default is off
and the flag is inert in every other mode, but this is not an experimental
opt-in: in the one mode where the states exist the network-producer loader
force-enables it unconditionally (the \emph{forcing estimate\_sat\_clocks
+ estimate\_sat\_phase\_biases} branch in
\texttt{GnssConfigLoadNetwork}), and the mirror
\texttt{GnssConfig::applyNetworkConsumerCouplings} turns it back off for the
closed-loop consumer, which \emph{consumes} these states rather than
estimating them.  The user side imports the satellite phase bias as a
known SSR correction (\dcref{sec:ssr}{the SSR-corrections document}) or
absorbs it into the float
ambiguity; the network instead carries an \emph{explicit}
per-(satellite, signal) phase-bias state on the undifferenced phase rows
(the estimable bias of \textcite{odijk2003fast}, lumping the network
pivot-receiver ambiguity).  On a single station's row it is co-linear
with the per-receiver float ambiguity and is separable only \emph{across}
stations in the joint network estimator (\dcref{sec:net}{the network-mode
document}).  It lives in a
\emph{distinct} state map from the satellite \emph{code} biases above
(\texttt{StateManager::sat\_phase\_bias\_indices\_}), keyed
\texttt{"<sat>|<signal>|PB"}, and is near-stationary between epochs at the
rate \texttt{sat\_phase\_bias\_q} --- which on the network path is applied
as the inflation of a shared-border \emph{carry prior}, not as a Kalman
$\Qmat(\dt)$ entry (see the satellite-clock paragraph below).

\paragraph{Receiver phase biases $\delta_{\rx,\sigl}$ (network mode).}
The receiver-side counterpart of the satellite phase bias, present only in
the network producer and gated by \texttt{network.phase\_datum\_eq34} (the
Eq-34 / single-receiver-chain phase datum; see \dcref{sec:net}{the
network-mode chapter}).  Giving the
receiver fractional phase bias its \emph{own} estimable state
$\delta_{\rx,\sigl}$ stops it lumping into the emitted satellite phase bias,
so the emitted between-satellite reference stays integer-consistent across
\emph{all} satellites (each chain hop then contributes only an integer).  It
is per (receiver, system, signal), keyed \texttt{"<system>\_RPB\_<signal>"}
in its own map (\texttt{StateManager::receiver\_phase\_bias\_indices\_}).
Structurally it is unlike every other bias block described here: these are
\emph{local} states, each observed by a single station.  Whether they carry
across epochs is a knob.  At
\texttt{network.phase\_datum\_eq34\_rpb\_q\_m2s} $=0$ each
$\delta_{\rx,\sigl}$ is re-estimated fresh every epoch (the original Card-3
behaviour); at the non-zero default the producer folds a local time-linking
prior toward the previous estimate with variance $\mathrm{var} + q\,\dt$,
which suppresses the per-epoch bounce that an only weakly observable local
state otherwise injects, anti-correlated, into every individual ambiguity
float.  That carry lives \emph{outside} \texttt{StateManager} --- in the
network run context (the \texttt{rpb\_carry} map of
\texttt{app/NetworkRunContext}), read during the parallel block assembly,
harvested post-solve, and erased for any $(\sat,\sigl)$ whose chain frame
stepped at that epoch's election (\texttt{filter/NetworkChainDatum}).  It is
forced off under \texttt{network.carry\_invariant}, where the loader warns
that the $q$ is inert.  Either way the receiver-side wander sinks into
$\delta_{\rx,\sigl}$ while the time-linked integer information stays in the
ambiguity carry.

\paragraph{Satellite clocks $\sLight\,\Delta\delta t^\sat$ (network mode).}
Also network-producer-only, gated by \texttt{estimation.estimate\_sat\_clocks}
--- like the phase bias above, off by JSON default and inert elsewhere, but
force-enabled unconditionally by the network-producer loader at the same
site.  The network estimates an
\emph{explicit} per-satellite clock correction $\Delta\delta t^\sat$ (in
metres, relative to the a-priori precise/real-time product clock already
removed from \texttt{obs.modeled}) so the emitted clocks stay consistent with
the chosen S-system datum.  It is \emph{per satellite}, not per signal --- one
state per satellite, with no signal field --- and the satellite \emph{orbit}
stays fixed from the product; only the clock is estimated.  It lives in a
distinct map (\texttt{StateManager::sat\_clock\_indices\_}), keyed
\texttt{"<sat>|SC"}.  Its cross-epoch rate \texttt{sat\_clock\_q} is
near-white, but on the network path it is \emph{not} a Kalman $\Qmat(\dt)$
entry: the producer runs no \texttt{KalmanFilter}
(\dcref{sec:kf}{the filtering document}), and the rate instead inflates the
shared-border carry prior as $\mathrm{var} + q\,\dt$.  The same holds for
\texttt{sat\_phase\_bias\_q} and \texttt{sat\_code\_bias\_q}; all three are
authorable either through their legacy \texttt{filter.process\_noise.*} keys
or through the network-scoped \texttt{network.process\_noise} class table,
whose per-class fallbacks equal those legacy defaults.  Between full solves
the emitted clock may additionally be refreshed by the split-cadence fast
tier (\texttt{network.fast\_clock}, default off and currently gate-failed);
that tier estimates a clock \emph{delta} in its own least-squares tick and
creates no state-vector row, so it does not appear here --- see
\dcref{sec:net}{the network-mode document}.

\paragraph{Inertial augmentation.}
When a tightly-coupled IMU is active the core state grows by nine
further entries --- a three-axis attitude error and the accelerometer
and gyroscope biases --- propagated by the strapdown mechanisation
rather than the random-walk process model.  These are treated in full
in \dcref{sec:imu}{the inertial-aiding document}.

\paragraph{Baseline differential troposphere.}
In baseline mode the per-station tropospheric, clock, ionosphere, and
bias states are absent; an optional single differential zenith-wet-delay
state $\Delta\zwd_{\rx_{\mathrm{rov}}\rx_{\mathrm{ref}}}$ may be carried
(\texttt{baseline.estimate\_differential\_tropo}, \Cref{sec:dd}).

\subsection{Dynamic indexing}\label{sec:state-indexing}

The variable-dimension blocks are addressed via key$\to$index maps
maintained by \texttt{StateManager}.  The canonical key formats are
defined once in \texttt{include/filter/StateKeySchema.hpp}, each with a
\texttt{make}/\texttt{parse} pair:
\begin{itemize}[leftmargin=*, itemsep=0pt]
\item iono key: \texttt{"<sys><prn>"}, e.g.\ \texttt{"G05"} (delimiter-free);
\item ambiguity key: \texttt{"<sys><prn>\_<signal>"}, e.g.\ \texttt{"G05\_L1C"}
      --- split on the \emph{first} underscore, so an iono-free combination
      \texttt{"G05\_L1C\_L5Q"} retains its compound signal;
\item satellite signal-bias key (code): \texttt{"<sys><prn>|<signal>"},
      e.g.\ \texttt{"G05|C1W"} --- a \emph{pipe} delimiter and a distinct
      map, \emph{not} the underscore ambiguity namespace;
\item satellite phase-bias key (network): \texttt{"<sys><prn>|<signal>|PB"},
      e.g.\ \texttt{"G05|L1C|PB"} --- the trailing \texttt{|PB} keeps it
      disjoint from the code-bias namespace, in its own map
      (\texttt{sat\_phase\_bias\_indices\_});
\item receiver phase-bias key (network): \texttt{"<system>\_RPB\_<signal>"},
      e.g.\ \texttt{"Galileo\_RPB\_L5Q"} --- the \texttt{\_RPB\_} infix keeps
      it disjoint from the receiver code-bias namespace (which matches on
      \texttt{IFB}/\texttt{DCB}), in its own map
      (\texttt{receiver\_phase\_bias\_indices\_});
\item satellite clock key (network): \texttt{"<sat>|SC"}, e.g.\
      \texttt{"G05|SC"} --- per satellite, \emph{not} per signal; the trailing
      \texttt{|SC} discriminator gives the clock its own map
      (\texttt{sat\_clock\_indices\_});
\item receiver code-bias key: \texttt{"<system>\_IFB<band>"} or
      \texttt{"<system>\_DCB"}; the per-slot GLONASS variant appends an
      FCN marker, \texttt{"GLONASS\_IFB<band>\_k<$\pm$slot>"} (e.g.\
      \texttt{"GLONASS\_IFB1\_k-4"});
\item inter-system time-offset key: the bare system name
      (\texttt{"Galileo"}, \dots; GPS is the reference and never appears);
\item double-difference ambiguity key (baseline):
      \texttt{"DD|<cons>|<sat>|<code>|<pivot>"}.
\end{itemize}
This single source of truth eliminates the off-by-one errors that
plague hand-managed dynamic state vectors and makes the BSSD/DD
S-transforms (\Cref{sec:diff}) implementable as block operations on the
relevant key sets.

Two further categories in the schema header are deliberately absent from
the list above, because they are not rows of $\stateV$: the BSSD pivot
absolute-seed lookup key (\texttt{"<cons>|<band>"}), and the shared
spherical-harmonic VTEC coefficient keys (\texttt{"SH|<n>|<m>|<C|S>"},
with the second shell carried on the distinct \texttt{SH2} prefix), which
name columns of the network estimator's \emph{shared border} rather than
\texttt{StateManager} states.  Both nonetheless follow the same
\texttt{make}/\texttt{parse} discipline, and both appear in
\dcref{tab:gen-state-keys}{the generated key-format table of the appendix}
--- machine-derived from the schema header, and therefore the completeness
reference against which the list above should be checked.

\paragraph{Ambiguity basis.}
By default the ambiguity block carries one per-band float ambiguity per
tracked (satellite, signal) in metres.  Setting
\texttt{estimation.state\_ambiguity\_basis = "nl\_wl"} switches the
whole run to a narrow-lane\,/\,wide-lane parameterisation: per satellite
a narrow-lane state (key \texttt{"<sat>\_NL\_<band>"}) and one wide-lane
state per band pair (\texttt{"<sat>\_WL\_<a>\_<b>"}, semantically
$N_a - N_b$), both in \emph{cycles} rather than metres so the wide-lane
and \textsc{lambda} arithmetic stays native to integers, with the
wavelength scaling moved into the Jacobian.  The two bases never coexist
in a single state vector.
