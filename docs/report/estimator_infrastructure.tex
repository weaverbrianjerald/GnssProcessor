\section{Estimator Infrastructure: WLS Seeding, State Initialisation, and Pivot Management}\label{sec:estinfra}
% ============================================================
%  Estimator-support machinery: bootstrap and re-reference
% ============================================================

% Doc-local symbols (descriptive names to avoid package collisions)

\newcommand{\wlsweight}{\bm{W}}                 % WLS diagonal weight matrix
\newcommand{\wlsstate}{\bm{\xi}}                % WLS core state [r, c dt, ZWD]
\newcommand{\mapw}{m_w}                          % wet mapping function
\newcommand{\coderes}{\widetilde{z}}            % prefit residual after modelled terms
\newcommand{\medop}{\operatorname{med}}         % median operator
\newcommand{\isbsys}{\mathrm{ISB}}              % inter-system bias seed
\newcommand{\pclk}{\delta_{\Phi}}              % phase-clock state
\newcommand{\ionoest}{\widehat{I}}              % per-sat slant iono estimate
\newcommand{\biascoef}{\beta}                   % receiver-bias Jacobian coefficient
\newcommand{\stransform}{\bm{T}}                % S-transform / re-referencing matrix

                                                % innovation covariance elsewhere)

The Kalman filter of \dcref{sec:kf}{the filtering document} is a
\emph{local} linear estimator.  Every update assumes the state is close
to the linearisation point.  Every dynamic state (ambiguity,
per-satellite ionosphere, receiver code bias, satellite bias, or
inter-system offset; \dcref{sec:state}{the state document}) needs a
value and a covariance before it can be updated.  This document covers
the machinery that provides them:
\begin{itemize}[leftmargin=*]
\item the weighted-least-squares (WLS) epoch solve, which places the
      receiver close enough for the linearisation to hold
      (\Cref{sec:estinfra-wls});
\item the first-epoch seeds formed from residual differences, which give
      each new state a physically reasonable prior
      (\Cref{sec:estinfra-init});
\item the between-satellite pivot selection and disturbance logic, which
      keep the single-difference (SD) reference stable across an arc
      (\Cref{sec:estinfra-pivot}).
\end{itemize}
None of this is filtering.  It is what makes the filter's local-linear
assumptions valid at the first epoch and after every discontinuity.

The lossless covariance re-referencing (the
$\stransform\,\covM\,\stransform^\Tr$ S\nobreakdash-transform that moves
a group onto a new pivot) is \emph{out of scope} here.  It is derived in
\dcref{sec:diff}{the differencing document} and implemented once in
\texttt{include/filter/CovarianceReReference.hpp}, which both the
single-receiver and the network handover paths call.  This section notes
where the pivot logic calls it.

% ============================================================
\subsection{The WLS epoch estimator: receiver-clock seed and post-gap re-seed}
\label{sec:estinfra-wls}
% ============================================================

Before the filter can run, the receiver position must be close enough to
the truth that the geometry Jacobian
\dcref{eq:geom-linear}{linearised about it} is valid to below a
decimetre.  Broadcast pseudoranges are sufficient for this.  The engine
runs a GPS-only, code-only iterated Gauss--Newton solve over the core
state
\begin{equation}
\wlsstate = \begin{bmatrix} \rxpos^\Tr & \sLight\,\mathrm{d}t_\rx & \zwd \end{bmatrix}^\Tr
\in\mathbb{R}^{5},
\label{eq:estinfra-wls-state}
\end{equation}
with $\rxpos\in\mathbb{R}^3$ the ECEF receiver position, $\sLight\,\mathrm{d}t_\rx$
the receiver clock in metres, and $\zwd$ the zenith wet delay
(\texttt{src/core/math/WlsEstimator.cpp}).  At least
\texttt{kCoreSize}~$=5$ code observations are required before the solve is
attempted; the iteration cap is \texttt{kMaxIter}~$=5$.

For each code measurement $\sat$ the prefit residual removes every modelled
term and the current state's contribution,
\begin{equation}
\coderes_\sat = \code_\sat
  - \bigl[\,\code_\sat^{\mathrm{mod}} + (\geomrange_\sat - \geomrange_\sat^{0})
  + \sLight\,\mathrm{d}t_\rx + \mapw(\sat)\,\zwd \,\bigr],
\label{eq:estinfra-wls-prefit}
\end{equation}
where $\code_\sat^{\mathrm{mod}}$ is the modelled pseudorange,
$\geomrange_\sat-\geomrange_\sat^{0}$ the change in geometric range relative
to the range at the iteration's linearisation point, and $\mapw(\sat)$ the
wet mapping function (\texttt{WlsEstimator::predictObs}, evaluated once per
row from the design-row loop of \texttt{WlsEstimator::estimate}).  The
geometric range is \emph{re-evaluated every iteration} about the current
position estimate, so each iteration is a Gauss--Newton
relinearisation.

The design row for satellite $\sat$ is the negated line-of-sight stacked with
the clock and wet-mapping partials, assembled in the same loop:
\begin{equation}
\wlsdesign_\sat = \begin{bmatrix} -\los_\sat^\Tr & 1 & \mapw(\sat) \end{bmatrix}
= \begin{bmatrix} -e_x & -e_y & -e_z & 1 & \mapw(\sat) \end{bmatrix},
\label{eq:estinfra-wls-row}
\end{equation}
with $\los_\sat$ the receiver-to-satellite unit vector (the same line-of-sight
that drives \dcref{eq:los}{the observation geometry}).  Stacking all rows into
$\wlsdesign$, the prefit residuals into $\coderes$, and the inverse measurement
variances onto the diagonal weight $\wlsweight$ (clamped from below by
\texttt{kMinVariance}~$=10^{-6}$ in that same loop), the
normal-equations step is the boxed Gauss--Newton update
\begin{empheq}[box=\fbox]{equation}
\Delta\wlsstate = \bigl(\wlsdesign^\Tr \wlsweight\, \wlsdesign\bigr)^{-1}
                  \wlsdesign^\Tr \wlsweight\, \coderes,
\label{eq:estinfra-wls-step}
\end{empheq}
applied once per Gauss--Newton iteration of \texttt{WlsEstimator::estimate}.
Iteration terminates on a position
increment $\lVert\Delta\rxpos\rVert < \texttt{kTol}=0.1\,\mathrm{m}$
or at \texttt{kMaxIter}.  The normal matrix is
guarded against rank deficiency: if
\begin{equation}
\det\!\bigl(\wlsdesign^\Tr \wlsweight\, \wlsdesign\bigr) \le 10^{-6}
\label{eq:estinfra-wls-detguard}
\end{equation}
the solve aborts and the epoch is not seeded (the determinant guard
immediately before the step).  This protects against degenerate
single-constellation, nearly coplanar geometry, which would otherwise
produce a very large position step.

On convergence the estimator returns both the state
$\wlsstate=[\rxpos^\Tr,\ \sLight\,\mathrm{d}t_\rx,\ \zwd]^\Tr$ and its formal
covariance, the inverse normal matrix
\begin{equation}
\covM_{\wlsstate} = \bigl(\wlsdesign^\Tr \wlsweight\, \wlsdesign\bigr)^{-1}
\label{eq:estinfra-wls-cov}
\end{equation}
(the result assembly at the end of \texttt{WlsEstimator::estimate}).  The
filter uses only the \emph{clock} from this result.
\texttt{Application::handleWlsSeeding} writes $\sLight\,\mathrm{d}t_\rx$
into the receiver-clock state when one of three triggers fires: the
first epoch, a data gap, or a clock \emph{jump} of at least
\texttt{kClockJumpThreshSec}~$=0.5\,\mathrm{ms}$ between the WLS and
filter clock estimates.  In practice the jump is the most common
trigger.

The position, the zenith wet delay, and the covariance
\eqref{eq:estinfra-wls-cov} are computed but are not used as filter
seeds.  The position prior is the RINEX-header
\texttt{approx\_position} plus the antenna offset.  The WLS position
re-seeds the filter only on a kinematic (non-IMU) cold start after a
long gap (\texttt{Application::handleGap}).  The ZWD estimate goes only
to a trace-CSV column, and nothing in the filter reads the formal
covariance.  The whole seeding path is skipped under BSSD, where the
filter has no receiver-clock state (\texttt{handleWlsSeeding} returns
early on \texttt{!hasClock()}).

The main use of the clock seed is \emph{re-seeding after a gap}.  The
receiver clock is the most volatile state across a data gap, because an
unsteered oscillator can drift freely while no measurements constrain
it.  After a gap the WLS clock estimate resets
$\sLight\,\mathrm{d}t_\rx$ before the phase filter resumes.  Otherwise
the filter would correct a stale clock prior through a series of large
innovations.

% ============================================================
\subsection{First-epoch state seeding by residual differencing}
\label{sec:estinfra-init}
% ============================================================

The WLS solve of \Cref{sec:estinfra-wls} seeds the receiver clock and, on
a kinematic cold start, the position.  It does not touch the
\emph{differential} states: inter-system bias, phase clock, uncombined
receiver code bias, per-satellite ionosphere, and carrier ambiguity.
Each of these is created empty and must be seeded from the measurement
residuals.  The common idea
(\texttt{src/core/measurement/StateInitializer.cpp}) is that each state
is what remains in a particular \emph{difference} of residuals after all
modelled terms are removed.  The seed is that difference, taken as a
median over satellites for robustness.
The shared prefit residual is
\begin{equation}
\coderes_{\rx,\sigl}^{\sat}
= \phaseo/\code_{\rx,\sigl}^{\sat}
  - \bigl(\mathrm{modelled}
  + \sLight\,\mathrm{d}t_\rx + \mapw\,\zwd + \isbsys + g_{\mathrm{trop}}
  + \alpha_\sigl \ionoest^\sat + \biascoef_\sigl b_\rx + b^\sat\bigr),
\label{eq:estinfra-rawres}
\end{equation}
the observation minus every term the model can already account for, evaluated
at the current state (\texttt{StateInitializer::computeRawResidual}, which
also forms the tropospheric gradient projection
$g_{\mathrm{trop}} = m_g(g_N\cos\mathrm{az} + g_E\sin\mathrm{az})$).  The
five \emph{differential} seeds (a)--(e) below are
differences of \eqref{eq:estinfra-rawres}; a sixth, network-only pre-seed~(f)
anchors the receiver clock itself.

\paragraph{(a) Inter-system bias.}  Each non-GPS constellation $g$ carries a
receiver clock offset relative to the GPS time scale
(\dcref{sec:state}{the inter-system offset state}).  The GPS clock is the
datum, and the WLS step has already put it into
$\sLight\,\mathrm{d}t_\rx$.  The ISB of $g$ is therefore the median code
residual of the constellation minus the median GPS residual:
\begin{empheq}[box=\fbox]{equation}
\isbsys_g = \medop_{\sat\in g}\ \coderes^{\sat}
          - \medop_{\sat\in\mathrm{GPS}}\ \coderes^{\sat}
\label{eq:estinfra-isb}
\end{empheq}
(\texttt{StateInitializer::initializeInterSystemBiases}).  Medians are used
throughout, so one gross code outlier cannot spoil the seed.  A guard
requires at least one GPS code observation at the seeding epoch (the
GPS-median guard in the same routine).  If GPS is absent the routine
returns \texttt{false} and \emph{tries again at the next epoch}.  It does
not mark the ISB states as initialised against an arbitrary datum.
Without the guard, whichever constellation is acquired first would
become the implicit zero, and a GPS satellite rising later would then
carry the whole offset.

\paragraph{(b) Phase clock.}  In the uncombined model the phase observations
see a receiver clock that differs from the code clock by the receiver
phase--code hardware delay (\dcref{sec:state}{the phase-clock state}).  Its
seed is the median over satellites carrying \emph{both} a code and a phase
observation of the code-minus-phase residual:
\begin{equation}
\pclk = \medop_{\sat}\ \bigl(\coderes^{\sat}_{\code} - \coderes^{\sat}_{\phaseo}\bigr)
\label{eq:estinfra-pclk}
\end{equation}
(\texttt{StateInitializer::initializePhaseClockOffset}).  The covariance of
the seed is set from the code noise.  It is tighter than the default
initial standard deviation, and it does not depend on the number $n$ of
differences in the median (the covariance-seeding code at the end of
that routine):
\begin{equation}
\sigma_{\pclk} = \max\!\Bigl(\tfrac{\sigma_{\code}}{\sqrt{n}},\ \sigma_{\code}\Bigr),
\qquad
\covM(\pclk,\pclk) = \sigma_{\pclk}^{2},
\label{eq:estinfra-pclk-cov}
\end{equation}
The corresponding row and column of $\covM$ are set to zero first, so
the seeded state starts uncorrelated.  Since
$\sigma_{\code}/\sqrt{n}\le\sigma_{\code}$ for every $n\ge1$, the $\max$
always selects $\sigma_{\code}$, and the seeded variance is
$\sigma_{\code}^{2}$ whatever the value of $n$.  The seed is floored at
the noise of a single code measurement and does not improve as
$1/\sqrt{n}$.

\paragraph{(c) Uncombined receiver code bias / IFB.}  In the uncombined
PPP-RTK model each non-reference code band carries a receiver differential
code bias (DCB) or inter-frequency bias (IFB) state relative to the
constellation's BIA clock-reference band
(\dcref{sec:state}{the code-bias state}).  Forming the residual difference
between band $j$ and the reference band, removing the differential ionospheric
contribution (the two bands scale the same slant ionosphere by different
$\alpha$), and dividing by the difference of receiver-bias Jacobian
coefficients gives
\begin{empheq}[box=\fbox]{equation}
\widehat{b}_{\rx,j}
= \frac{\Delta\coderes_j - \Delta(\alpha_j\,\ionoest)}{\Delta\biascoef_j}
= \frac{(\coderes_j - \coderes_{\mathrm{ref}})
        - (\alpha_j - \alpha_{\mathrm{ref}})\,\ionoest^\sat}
       {\biascoef_j - \biascoef_{\mathrm{ref}}}
\label{eq:estinfra-codebias}
\end{empheq}
(\texttt{StateInitializer::initializeCodeBiases}), median-aggregated over satellites and
subject to the same $\lvert\widehat{b}\rvert > 200\,\mathrm{m}$ reject as the
ionosphere seed below.  The Jacobian coefficient $\biascoef_\sigl$ depends on
the bias parameterisation (\texttt{StateInitializer::resolveReceiverBias}):
for a pure
IFB state it is the unit coefficient $\biascoef = 1$, whereas for a
geometry-free / ionosphere-free DCB state against reference bands of
frequencies $f_1,f_2$ it is
\begin{equation}
\mu_1 = 1, \quad \mu_2 = \frac{f_1^2}{f_2^2}, \quad
\Delta\mu = \mu_1 - \mu_2, \qquad
\biascoef_j = \begin{cases} \mu_1/\Delta\mu & j = \text{band }1 \\[2pt]
                            \mu_2/\Delta\mu & j = \text{band }2, \end{cases}
\label{eq:estinfra-bias-coef}
\end{equation}
guarded by $\lvert\Delta\mu\rvert \ge 10^{-12}$ to avoid dividing by a
near-degenerate frequency separation.

For GLONASS a third branch runs before both cases.  Under
\texttt{enable\_glonass\_ifb} each FDMA band (G1, G2) has one bias state
\emph{per FCN slot} $k$ with $\biascoef = 1$
(\texttt{StateKeys::makeGlonassPerSlotIfbKey}).  The per-slot carrier
$f = f_{\mathrm{base}} + k\,\Delta f$ makes the receiver group delay
depend on the slot, which one state per band cannot represent.  The
central channel $k=0$ is the datum and has no state.  The CDMA bands
(G3/G4/G6) use the per-band treatment above.  The branch runs before the
clock-reference lookup because GLONASS usually has no clock-reference
pair in the \texttt{.BIA} product, and the routine would otherwise
return before reaching any IFB logic.  With the flag off, a
non-reference GLONASS band has no IFB state (the per-slot and
non-reference-band branches of \texttt{resolveReceiverBias}).

\paragraph{(d) Per-satellite slant ionosphere.}  Each tracked satellite's
slant ionospheric delay (\dcref{sec:state}{the per-satellite iono state}) is
recovered from the geometry-free combination of two code bands.  With
ionospheric scale factors $\alpha_\sigl = f_{\mathrm{ref}}^2/f_\sigl^2$
referenced to GPS~L1 (\dcref{eq:iono-scaling}{the iono-scaling convention}),
the seed is
\begin{empheq}[box=\fbox]{equation}
\ionoest^\sat
= \frac{(\code_1 - \code_1^{\mathrm{mod}}) - (\code_2 - \code_2^{\mathrm{mod}})}
       {\alpha_1 - \alpha_2}
\label{eq:estinfra-iono}
\end{empheq}
(\texttt{StateInitializer::computeIonosphereSeed}), where $\code_k^{\mathrm{mod}}$ is the
modelled pseudorange on band $k$.  Two guards apply.  The denominator
must satisfy $\lvert\alpha_1-\alpha_2\rvert \ge 10^{-6}$.  The seed is
rejected unless it is finite and
$\lvert\ionoest^\sat\rvert < 200\,\mathrm{m}$.  A slant ionospheric delay
above $200\,\mathrm{m}$ is not physical.  It indicates mis-paired bands
or a gross code outlier, and must not be stored in a per-satellite
state.

Two BIA-coverage gates also apply, so that the differenced code is
consistent in its biases.  The first is \emph{presence}: a \texttt{.BIA}
entry exists on the band, with the zero-valued BeiDou C2I/C6I entries
treated as missing.  The second is coverage \emph{honesty}
(\texttt{bias\_coverage\_requires\_apply}).  It skips the seed when an
entry is loaded but not \emph{applied} to $(P-\mathrm{mod})$, because the
raw hardware bias is then still present.  The network producer uses
presence only.  The honesty gate is needed because the failure it
prevents, a zero-valued BeiDou entry that injects
$30$--$60\,\mathrm{m}$, is well below the $200\,\mathrm{m}$ reject and
would pass it.

\paragraph{(e) Carrier ambiguity.}  The float ambiguity that subsequently feeds
integer resolution (\dcref{sec:ar}{the ambiguity-resolution document}) is
the part of the \emph{phase} residual that remains after every other
modelled and estimated term is removed
(\texttt{StateManager::computeAmbiguitySeed}, the routine that every
phase-seeding call site uses),
\begin{equation}
\widehat{N}^\sat_{\rx,\sigl}
= \phaseo^\sat_{\rx,\sigl} - \mathrm{modelled}
  - \bigl(\sLight\,\mathrm{d}t_\rx + \pclk\bigr) - \mapw\,\zwd
  - \isbsys - g_{\mathrm{trop}} + \alpha_\sigl\,\ionoest^\sat,
\label{eq:estinfra-amb}
\end{equation}
This is the phase observation minus its model, the receiver clock
\emph{and} the phase clock $\pclk$ (seed~(b)), the wet delay, the
inter-system bias, and the tropospheric gradient, plus the slant
ionospheric phase advance $+\alpha_\sigl\,\ionoest^\sat$ (seed~(d)).  The
phase is advanced by the same $\alpha_\sigl$ that delays the code, so
the iono term has the opposite sign to \eqref{eq:estinfra-rawres}.  The
phase clock and the slant iono are removed because they are estimated
states in the uncombined model.  One term cannot be removed this way: a
receiver clock that is still zero on a network cold start.  Pre-seed~(f)
handles that case.

The seeded ambiguity therefore contains the integer cycle count plus the
remaining receiver and satellite phase biases.  AR recovers the integer
part once the satellite phase bias is supplied and the receiver phase
bias cancels under between-satellite differencing.

\paragraph{(f) Cold receiver-clock pre-seed (network path).}  Seeds (a)--(e)
assume the receiver clock has already been solved.  That holds on the PPP
path, where the WLS clock seed of \Cref{sec:estinfra-wls} runs first.
The network producer does not run the WLS seed, so nothing solves the
receiver clock before the ambiguity of (e) is seeded.
\texttt{computeAmbiguitySeed} then subtracts a clock term of zero, and
the whole free-running receiver-clock offset goes into every cold
ambiguity seed.

The opt-in \texttt{seedColdReceiverClock}
(\texttt{network.cold\_clock\_seed}, default off) fixes this.  It writes
the median GPS code residual into $x(\mathrm{clock})$.  This is the
\texttt{gps\_median} that ISB seed (a) computes and discards.  The seed
overwrites only a \emph{cold} clock.  Any
$\lvert x(\mathrm{clock})\rvert > \texttt{kColdClockEpsilonM} = 10^{-6}\,\mathrm{m}$
is treated as already solved and is left unchanged.  When the epoch has
no GPS code observation the routine returns \texttt{false}, so it tries
again at the next epoch and does \emph{not} mark the clock as seeded.
This matches the GPS-reference contract of seed (a)
(\texttt{StateInitializer::seedColdReceiverClock}).

\subsection{BSSD pivot management}
\label{sec:estinfra-pivot}
% ============================================================

Between-satellite single differencing (BSSD, \dcref{sec:bssd}{the BSSD
document}) re-expresses each constellation's ambiguities relative to a
designated \emph{pivot} satellite $\piv{g}$.  This cancels the receiver
phase bias and makes the SD ambiguities integer.  The choice of pivot
matters.  A poor pivot degrades every SD row that references it, and an
unstable one forces costly re-referencing handovers.
\texttt{src/core/filter/PivotManager.cpp} selects and maintains the
pivot.  The baseline double-difference path uses the similar
\texttt{src/core/filter/DdPivotManager.cpp}.

\subsubsection{Lexicographic candidate ranking}
\label{sec:estinfra-pivot-rank}

Candidates are ordered \emph{lexicographically}: first by a
signal-coverage tier, then by a continuous score within the tier.
Coverage comes first because the pivot must track every signal that any
non-pivot satellite tracks.  A non-pivot signal that the pivot lacks has
no reference and is dropped.  \emph{Any} full-coverage candidate
therefore ranks above \emph{any} partial-coverage candidate, whatever
their scores (the lexicographic comparator in
\texttt{PivotManager::buildEpochMaps}).  Candidate $a$ beats $b$ if and
only if its phase-signal count is higher, or the counts are equal and
its score is higher.

Within a coverage tier the tie-break score combines float-convergence and
geometry (\texttt{PivotManager::scorePivotCandidate}):
\begin{empheq}[box=\fbox]{equation}
\mathrm{score}(\sat) =
  -\min\!\bigl(1,\ \sqrt{\,v_{\max}(\sat)\,}\bigr)
  + \frac{\mathrm{el}(\sat)}{90}
  - \tfrac{1}{2}\,\mathbb{1}\!\left[\mathrm{el}(\sat) < 20^\circ\right],
\label{eq:estinfra-pivot-score}
\end{empheq}
where $v_{\max}(\sat)$ is the worst (largest) float-ambiguity variance among the
satellite's tracked phase signals and $\mathrm{el}(\sat)$ is its elevation in
degrees.

The first term penalises a pivot that has not converged.  On handover
the new pivot's variance is added to every SD state in its group.  This
is the diagonal of the \dcref{sec:diff}{S-transform},
$\covM'(i,i)=\covM(i,i)+\covM(\piv{g},\piv{g})-2\covM(i,\piv{g})$,
implemented in \texttt{include/filter/CovarianceReReference.hpp}.  A
pivot whose own state is still settling therefore passes its uncertainty
to the whole constellation.  The penalty saturates at $-1$, equivalent
to one metre of $1\sigma$ ambiguity uncertainty.  A candidate with
\emph{no} state yet receives a flat $-1$ (the
negative-\texttt{max\_amb\_variance} sentinel branch of the score).  On
the first BSSD epoch every candidate in a tier has this sentinel, so the
score reduces to elevation and no special first-election branch is
needed.

The $\mathrm{el}/90$ term prefers high-elevation pivots.  The
$-\tfrac12$ penalty below $20^\circ$ discourages a low pivot, whose
tropospheric and multipath residuals exceed the formal stochastic model
however well its float state has converged.

Both terms only \emph{rank} candidates that have already passed a hard
elevation gate.  A satellite below \texttt{pivot\_min\_el}
(\texttt{getBssdPivotMinElevation}) cannot be elected at all: not in the
freshest-peer scan, not in the online pick, and not in the
sticky-retention test, all three in
\texttt{PivotManager::selectPivotCandidates}.  The $-\tfrac12$ penalty
therefore only breaks ties among the survivors.  When \emph{no}
satellite passes the mask (a code-only float constellation), the gate is
bypassed.  The pick reverts to the precomputed best or highest-elevation
satellite, so the candidate set is never empty (the fallback from
\texttt{pickExclusionAwareBest} to the precomputed \texttt{best\_sat} /
\texttt{highest\_sat}).

Sticky retention is the code's \emph{elevation hysteresis}, and it
prevents the pivot changing back and forth between epochs.  It uses the
same \emph{absolute} gate and does not compare the incumbent with a
challenger.  The incumbent is kept whenever it still passes
\texttt{pivot\_min\_el}, is not excluded, and stays within the toe
spread of \Cref{sec:estinfra-pivot-toe} (the sticky branch of
\texttt{selectPivotCandidates}).  No score is evaluated on that branch,
so a better challenger cannot displace a qualifying incumbent.  The
score ranking runs only after the incumbent has \emph{failed} the gate.

\subsubsection{Ephemeris-freshness guardrail}
\label{sec:estinfra-pivot-toe}

A pivot with a stale broadcast ephemeris puts a step into \emph{every} SD
row that references it.  Its extrapolated orbit and clock drift away
from those of the fresher satellites it is differenced against.  This
was observed in production: a Galileo pivot held a one-hour-old I/NAV
record while the other satellites' records were minutes old, and the
whole SD solution was corrupted.  The guardrail is gated on the
\emph{spread} of ages.  A
candidate is barred from pivot election when its absolute ephemeris age
$\lvert t_{\mathrm{obs}} - t_{\mathrm{oe}}\rvert$ exceeds the constellation's
freshest qualified peer by more than
\begin{equation}
\texttt{kPivotToeSpreadMaxS} = 1200\ \mathrm{s} = 20\ \mathrm{min}
\label{eq:estinfra-pivot-toe}
\end{equation}
(the \texttt{freshestToeAgeAbs} scan in
\texttt{PivotManager::selectPivotCandidates}, applied both at the online
pick and at the sticky-retention test).  Because the gate is on the
\emph{spread} and not on an absolute age, the ranking is unchanged when
all candidates are about equally fresh.  Only a candidate that is much
staler than the rest is displaced.  The barred satellite can still be
used as a non-pivot.  The freshest satellite always passes, since its
difference from itself is zero, so the candidate set is never empty.

\subsubsection{Pivot disturbance detection and handover}
\label{sec:estinfra-pivot-dist}

In BSSD the pivot's own SD ambiguity is zero with zero variance, because
the pivot \emph{is} the reference: $x(\piv{g}) = 0$ and
$\covM(\piv{g},\piv{g}) = 0$ exactly.  Any departure from that state
means the filter has perturbed the reference, through process noise or
an update, and the SD states are no longer consistent.
\texttt{isPivotDisturbed} flags this when, for any of the pivot's phase signals,
\begin{empheq}[box=\fbox]{equation}
\bigl\lvert x(\piv{g})\bigr\rvert > 10^{-6}
\quad\text{or}\quad
\covM(\piv{g},\piv{g}) > 10^{-12}
\label{eq:estinfra-pivot-disturbed}
\end{empheq}
(\texttt{PivotManager::isPivotDisturbed}).  The two thresholds are
tolerances for numerical zero, not tuned gates.  $10^{-6}\,\mathrm{m}$ on
the value and $10^{-12}\,\mathrm{m}^2$ on the variance catch any real
leakage onto the pivot and tolerate floating-point round-off in the
re-reference arithmetic.  The predict step must not create a false
disturbance, so the pivot's process noise is suppressed during
prediction and $\covM(\piv{g},\piv{g})$ stays at zero
(\dcref{sec:kf}{the freeze-state / $\Qmat$-suppression mechanics}).
Without the suppression, every epoch's $\Qmat$ would trip
\eqref{eq:estinfra-pivot-disturbed} and force an unnecessary handover.

A handover fires when the incumbent is disturbed or when the ranking
elects a different satellite.  The outgoing pivot is then classified.  In
a \emph{clean} handover the old pivot's state is invertible and
consistent.  It can be re-referenced without loss, and the RTS smoother
can later invert it.  A \emph{forced} or disturbed handover cannot be
inverted cleanly and marks a discontinuity.

In both cases \texttt{CovReReference::applyBssd} in
\texttt{include/filter/CovarianceReReference.hpp} re-references the
covariance in place.  It subtracts the new pivot's row and column from
each non-pivot member of the group, then sets the new pivot's row and
column to zero.  This is the one shared implementation of the
$\stransform\,\covM\,\stransform^\Tr$ transform
\dcref{sec:diff}{derived in the differencing document}.

The baseline DD path has a different structure.  It negates the
new-pivot row and column and subtracts from the others, which is a
different S-transform, and then renames the affected ambiguity states
with \texttt{StateManager::renameAmbiguity}
(\texttt{DdPivotManager::handleHandover}).  The two paths share only the
positive-definiteness guard applied after the transform
(\texttt{enforcePsd}).  The single-receiver user path runs the transform
without the guard.  At user scale the groups are small and handovers are
rare, so floating-point error in
$\stransform\,\covM\,\stransform^\Tr$ does not accumulate.
