# Config ledger: one verdict per config key

[`CONFIG_promotion_ledger.json`](CONFIG_promotion_ledger.json) is the ledger and the authority:
one row per config key the network loader reads (plus the few other-section keys a network
posture depends on) with its verdict, default, golden value, one-sentence reason and evidence
card. The text below the GENERATED marker is rendered from it by `scripts/ledger_render.py`. The
posture is the two goldens in `config/golden/`, generated by `scripts/make_golden_config.py` from
`golden_manifest.json` and this JSON, never hand-edited; a knob is armed only at the author's
decision through a ledger row and the generator. Topic page: [config-ledger](topics/config-ledger.md);
the user-facing knob reference is [CONFIG.md](CONFIG.md).

## How a ledger change is made

1. Edit the key's row in `docs/CONFIG_promotion_ledger.json` (a new key gets its row in the
   commit that adds it). To arm a knob, also pin it in `config/golden/golden_manifest.json` and
   run `python scripts/make_golden_config.py`.
2. `python scripts/ledger_render.py`.
3. `python scripts/make_golden_config.py --verify`: fails on an in-regime RECOMMEND_* row a golden
   leaves unarmed outside the manifest's `exceptions`, on a stale exception, on a pin that does
   not read back.
4. `python scripts/config_posture_check.py --verify-loader`: 0 gaps (RECOMMEND_* rows against the
   loader's posture table in both directions, predicate syntax, the `on()` trap).
5. A RECOMMEND_ON / RECOMMEND_SCOPED row needs `regime`, `posture_why`, `armed_when` for a value
   knob, `fingerprinted` for a fingerprint member, and a row testing the same predicate in
   `src/core/config/GnssConfigNetworkPosture.cpp` (`appendNetworkPostureItemsOn_` /
   `..Scoped_`); a demotion removes that row.
6. `python scripts/docs_index_check.py` before the commit.

## Machine fields

The loader's run-start POSTURE block, `config_posture_check.py <config> --tier all` (offline)
and `make_golden_config.py --verify` evaluate the same predicates.

**`regime`**: a row is reported only where it is true, because a knob validated at one scale can
harm at another (the retired `mw_wl.bridge_sample_debias`: good at 50 stations, wrong-integer
rate 0.0 % to 12.5 % at 305). `"True"` is unconditional; `"False"` marks a recommended key that is deliberately
not a posture row (`posture_why` says why); a RECOMMEND_* row without one is a gap.

| token | meaning |
| --- | --- |
| `n_sta`, `n_sys` | station count; length of `processing.active_systems` |
| `tri` | `frequency_mode` triple or all |
| `warm` | resumed leg: the loader tests that `state_snapshot_path` is set, the checker that the snapshot exists (undecidable reads warm) |
| `rt` | real-time `app_mode` or `network.service_mode` |
| `pstations`, `par` | `parallel_stations` (default true); and `n_sta` > `parallel_min_stations` (default 10) |
| `gps_only`, `gps_gal_only` | constellation set by name (a count admits GPS + BeiDou) |
| `spacing_s` | `gnss_rate_s` × `epoch_decimation_n` (0 at the native rate) |
| `on("k")` | key present and not false, 0 or empty |
| `val("k", d)` | the key's value, else `d`, which must be the C++ loader default |

Only these, `v` / `found` (in `armed_when`) and plain operators parse.

**`armed_when`** replaces truthiness where it misreads: a string enum with a truthy default
(`ambiguity_vehicle` `"level"`), a list, a threshold, or a set of keys (the exact update with
`clock_anchor_guard_space` phase and `rank_gate_tol` 1e-11). It sees `v` and `found`.

**`fingerprinted`** marks a key of the warm-resume fingerprint (`networkSnapshotFingerprint`,
`src/core/app/NetworkSnapshotFingerprint.cpp`). CHAIN rule: a resumed leg cannot adopt one; arming it
hard-aborts the leg under `state_snapshot_require` and otherwise silently cold-starts it as a
clean-looking resume (invariant #4), so it is armed in a fresh lineage, and both readouts print a
CHAIN line on a warm config. The posture is fresh convergence only; `ctu_switch_on_resume` (the
switch-on seam, failed card CTU2's G5) stays off.

**The `on()` trap.** `on()` is false for an absent key, so it inverts on a key whose loader
default is true (once every parallel predicate, through `parallel_stations`); such a key takes
`val("k", True)`, and `--verify-loader` fails on `on()` of one.

**Bundles** (`networkPostureBundles_`): keys correct only together; an engaged bundle partially
armed logs a warning. Members need no RECOMMEND_* row.

| bundle | engaged when | members | goldens |
| --- | --- | --- | --- |
| zero-q phase memory + slip response | `phase_leveling` or `carry_invariant` | `cycle_slip.mw_detect`, `cycle_slip.if_phase_td` | complete |
| armed QC set | `raim` | `raim_attribution`, `raim_within_epoch`, `clock_runaway_check` | complete |
| SH-VTEC / W6 slice | `estimate_iono_sh` | `ionosphere_weighting.enable`, its cutoff ≥ 25 deg, `estimate_sat_code_bias` | not engaged (no SH) |

## Notes

1. Grade datum-invariant quantities on the cold 6 h consumer and the 16-site census against a
   same-exe control at the same thread count; a `parallel_carry` result reproduces only at the
   same exe and thread count ([NETWORK_REFOUNDING](refound/NETWORK_REFOUNDING_2026-09-14.md),
   [MSC](refound/MSC_multi_site_consumer_2026-09-21.md)).
2. The loader overrides config values, so the run manifest and load log record what ran:
   `raim_within_epoch` arms `raim` + `raim_attribution`, `phase_leveling` without a detector arms
   `cycle_slip.mw_detect`, code-bias estimation turns
   `model_corrections.enable_code_phase_bias` off, `service_mode` overrides explicit false values
   (`GnssConfigLoadNetwork.cpp`).
3. `filter.process_noise.clock_bias_q` is inert on the network producer (the receiver clock is a
   free per-epoch column; measured byte-identical, `GnssConfigLoadNetwork.cpp`).
4. Post-fit `raim` and the clock monitor run after emission and protect the next epoch;
   `raim_within_epoch` alone adapts an epoch before it is emitted (`ApplicationNetwork.cpp`).
5. Only the health trace is flushed during a run; other traces close at teardown, so a killed run
   loses their tails and `trace_flag_rates` writes nothing (`NetworkRunTraces.cpp`).
6. A producer and its consumers share one wind-up mode (the census gain is the accumulating
   consumers' own), and a sim fixture sits on the producer's side of the wind-up sign fix
   ([WUP](refound/WUP_windup_accumulated_promotion_2026-10-01.md),
   [wind-up sign](cards/network-vehicle/WINDUP-SIGN-DEFECT.md)).
7. Golden arms are GPS + Galileo since A16: `rapid_arm.py score` pools E5a with band 5,
   `ftc_step_attrib.py` R3 needs `--systems G,E`, and `census6h.py` / `simcensus6h.py` default
   to GPS-only bases where `gcensus.py` does not ([GAD](refound/GAD_galileo_adoption_2026-10-13.md)).
8. The sim golden starts inside the fixture's start artifact, so the sim is graded from 00:30:15
   ([EXL](refound/EXL_exact_update_lah_promotion_2026-10-01.md) section 4).
