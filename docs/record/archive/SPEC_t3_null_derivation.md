# SPEC — the T3-class null: the statistic is scale-blind, so the defect is in the POOL

QUEUE item 4 (`docs/QUEUE_principled_replacements.md`): *"T3-class test statistics: correct nulls,
not recalibrated constants."*  Written 2026-08-14, fitting on `runs/pareref_on` — the null instrument
regenerated by item 1(d) (`SPEC_pivot_visibility_gauge_defect.md` §5.08).

**Headline.**  The bandaid is a Gaussian 6σ constant; the reflex replacement is a corrected
extreme-value quantile.  **Both are wrong, and for the same reason: the statistic cannot see scale
at all.**  It is a ratio of two functionals of the same pool, so any common rescaling of the
residuals cancels exactly — proven by an A/B that rescales every row by **×1.45** and moves the
statistic's median by **×1.025**.  What it *does* see is the pool's internal heterogeneity, and on a
fixture where every station draws the **same** error model that heterogeneity is a **4.7×**
multiplicative station effect and a **2.75×** signal effect.  Removing the station axis alone, fitted
out-of-sample, cuts the false-alarm rate **4.46 % → 0.97 %** at **zero cost in detection power**
(§13: 20/24 injected slips, byte-identical per-rung, 3.9× fewer flags).  The correct replacement is a
**stratified studentization**, not a new threshold.

✅ **MECHANISM (§7.8): the per-station heterogeneity is per-LOS IONOSPHERE ESTIMATION ERROR**,
truth-graded — corr(log station variance factor, log datum-free iono error rms) = **+0.9258**, error
rms 0.11–2.55 m by station.  The per-arc ambiguity absorbs ~96 % of it; the unabsorbed ~4 % lands in
the phase residual in the iono direction, which is L1-dominant.  Ten other candidates falsified
(§7.7).

⚠ **Field check (§12): the structure reproduces and is stronger — station spread 10.5×,
transferability +0.873 — but the remedy's leverage falls to 1.5×, because the field runs with σ̂₀
clamped at the 1.0 floor on 88–96 % of epochs.  In that regime the denominator is a constant and the
statistic is an unnormalized max, so there is nothing for a stratified pool to fix.  Unclamping comes
first on the field.**

## 2. The invariance theorem — and why it decides the card

$S_c$ is **invariant under $z \mapsto \lambda z$ for any constant $\lambda$** whenever the floor is
not binding: numerator and denominator are both positively homogeneous of degree 1 in $z$.

⚠ When the floor **does** bind, $\hat\sigma_0 \equiv 1$ and $S_c = \lambda\max_{i\in c}|z_i|$ — fully
scale-*sensitive*.  That is not an escape; it is a second, independent defect: **the test is
non-pivotal**, switching between two different statistics depending on whether the epoch's robust
level happens to sit above 1.  On this arm the floor binds on 38 of 114 epochs (concentrated in
ignition), and those epochs average 1.97 flags against 9.51 on the unpinned ones.  In the settled
window $\hat\sigma_0 \in [1.3, 1.6]$, so the invariance argument applies where it matters — and §5
confirms it empirically end-to-end.

Three consequences, covering most of the "obvious" fixes:

1. **No global variance-model correction can change its false-alarm rate.**  Fixing the a-priori σ,
   the elevation weighting, or the redundancy standardization all rescale the pool nearly uniformly
   and therefore cancel.  §5 measures exactly this.
2. **A recalibrated constant `k` cannot work either**, and not only for the reason the pivot spec
   gave (rising implied-scale curve).  Under the *exact* null the shipped `k = 6` is **already
   stricter than a 10⁻⁶ per-cell test** (§3).  A threshold that is too strict cannot cause a 10⁷×
   excess.
3. **What is left is the pool's internal structure.**  $S_c$ measures a cell's position *relative to
   the median of its pool*.  If the pool is a mixture of sub-populations with different scales, the
   numerator is drawn from the widest component while the denominator tracks the most numerous one,
   and the ratio has no fixed null at all — its distribution depends on mixture weights that change
   every epoch as the station/satellite set changes.

  the threshold for α = 1e-6 is **5.10** with $\hat\sigma\equiv1$, **5.06** at $N=1400$, **5.00** at

  shipped test is *conservative*.

## 4. Measured: the pool is a mixture, where every station draws the SAME model

`config/sim/simnet24_inject.json` specifies a single global
`noise: {code_sigma_zen_m: 0.3, phase_sigma_zen_m: 0.003}` and **no `multipath` block**, so the
generator defaults apply network-wide (Gauss-Markov phase multipath, 2 mm zenith, τ = 300 s, 1/sin el
amplified to a 20° cap — `include/sim/SimConfig.hpp:150-169`).  Verified against the emitted
per-station child configs (`runs/simnet24_inject_null/_child_*.json`): each carries only its own
`station.seed_salt`, derived from the station name.  So **every station draws an independent
realization of the SAME error model, and there is no per-station σ anywhere in the generator.**
Independent realizations of a common model give a few percent of sampling spread in a robust scale,
not 4.7×.  A systematic per-station scale of that size is manufactured downstream of the data.

Settled window (> t₀+1800 s, `s_raw > 0`): 9975 cells over 53 epochs, 24 stations.

| axis | spread | source |
|---|---|---|
| **station** | **4.7×** (0.948 … 4.452) | fitted cell scale, `network_station_residuals.csv` |
| **signal** | **2.75×** (L2W 0.9974, L5Q 1.3325, **L1C 2.7435**) | `network_pf_keyed.csv` SIG rows, median `s0_phase`, settled window (over all 114 traced epochs: 0.9155 / 1.1656 / 2.3597 = 2.58×) |
| epoch | 1.3× (0.869 … 1.152) | fitted; i.e. the axis σ̂₀ *does* estimate is nearly irrelevant |

The signal axis sits **inside** the cell max — the cell is a max *across* L1C/L2W/L5Q, so it is
essentially always an L1C row, while the pooled median is dominated by L2W/L5Q.  This also rules out
elevation weighting: all three signals share an elevation and a weight at a given (station,
satellite, epoch).

Corroborating structure:

- Flags concentrate in **11 of 24 stations** and **40 (station,satellite) keys**; S20 carries 33.7 %
  of all 798 flags, S06 28.4 %, S01 16.7 %, S07 12.3 %.  Per-station flag rates run to **26.1 %**
  while 13 stations flag at **0.00 %**.
- Flags-per-epoch is **4.13× overdispersed** against Binomial(n_cells, p̂), and the cells are
  **strongly dependent in time**: within-arc lag-1 autocorrelation of `s_norm` is **0.8994** (21 555
  consecutive pairs), and P(flag at t+1 | flag at t, cell still present) = 653/789 = **0.8276**

  contiguous arc-runs on 40 (station,satellite) keys**.  This is the measurement R3 turns on: the
  family is nowhere near 21 788 independent tests.
- **No observational covariate explains it**: corr(log station scale, ·) = −0.20 (median elevation),

- **364 cells (1.67 %) have `s_raw` exactly 0** — a carried ambiguity with no phase row this epoch.

## 6. The principled replacement

**R1 — studentize per stratum, with a slow/fast split that the noise budget forces.**

$$\hat\sigma(s,t) \;=\; \hat\sigma_{\text{sta}}(s)\cdot\hat\sigma_{\text{net}}(t)$$

- $\hat\sigma_{\text{net}}(t)$ — the existing network-wide robust scale.  **Keep it.**  It is the
  fast channel, and epoch-common contamination is exactly what RAIM exists to catch.
- $\hat\sigma_{\text{sta}}(s)$ — a **slow**, robust, time-pooled per-station factor (EWMA of the
  station's robust residual level, normalized to network median 1), with a floor/ceiling and a
  minimum sample.

⚠ **SUPERSEDED IN FORM by §7.5** — the per-stratum factor should be the variance component
Σw·v²/Σr_i, not a median of cell maxima.  The slow/fast split and the noise budget below still stand;
only the estimator inside the slow factor changes.

The split is arithmetic, not style.  Relative SD of a robust scale from *m* rows,
$1.4826\sqrt{1/(4mf(q)^2)}$ with $f(q)=2\varphi(0.6745)=0.63556$:

| m | SD(σ̂)/σ | what |
|---|---|---|
| 564 | 4.91 % | network pool, one epoch |
| **23** | **24.32 %** | one station, one epoch — **too noisy to studentize against** |
| 415 | 5.73 % | one station, whole window |

A per-station-per-epoch scale would re-import a heavy tail from the *estimator*.  Pooling over time
is what makes it usable, and §4.1's +0.847 half-to-half correlation is what licenses the pooling.

**R2 — declare the stratum, do not absorb it.**  A per-station denominator makes the *cell* test
correct, but on a homoscedastic fixture the heterogeneity it divides out is model error, not noise.
Absorbing it silently would mask a real defect — the same failure mode as recalibrating `k` until the
alarm stops.  So the per-station factor becomes a **first-class declared statistic** with its own
event, counter and threshold: a station whose slow factor departs from the network is precisely the
"bad station" that T4's median-polish row effect was built for and that is currently deliberately
disabled (`NetworkRaim.cpp:434-439`, where `bad_stations` is declared and never populated at `:441`).
This is standing invariant #7 applied to a test statistic — the edge where a station gets its own
scale is an event at both sides, and both must be counted.

**R3 — set α by FDR over the family, not `k` by hand.**  With the pool stratified, the exact per-cell
null is usable directly (`exact_k(α, n_c)`).  But a fixed `k` has an implied family-wise α that
drifts with roster size and run length — 21 788 cells here, ~10× that at 305 stations.
Benjamini–Hochberg over the (cell × epoch) family is the right control.  ⚠ **BH's independence/PRDS
assumption is measurably violated here, and not marginally**: §4's within-arc lag-1 autocorrelation
is 0.8994 and P(flag | flag at t−1) = 0.83 against a 0.037 marginal, so the 21 788 "tests" are closer
to **145 arc-runs on 40 keys**.  Any FDR scheme must be applied to a family whose effective size is
set by the arc structure, not the cell count — and cells additionally share the σ̂₀ denominator and
the shared satellite states.  Benjamini–Yekutieli's $\sum_{i=1}^{M}1/i$ factor is the conservative
fallback; its cost should be measured rather than assumed.

**R4 — population hygiene (cheap, independent).**  Exclude the structurally untestable cells (`s_raw`
exactly 0, 1.67 %) from the T3 opportunity count, and give T3c an opportunity definition that matches
its conditional construction (§1) or drop its `implied_alpha` column, which currently compares a
conditional rate against an unconditional α.

**R5 — do NOT do.**  Do not arm `raim_redundancy_normalize` for this purpose **on this posture**:
measured null on the flag rate, +38 % runtime (§5).  ⚠ **Sim-scoped** — §12.2 shows the field runs
with σ̂₀ clamped at the floor on 88–96 % of epochs, where B2's ×1.45 lift would *unpin* the pool
rather than cancel.  A field B2 arm is owed before this line is read as general.  It may still be
right for MDB, which needs `r_i` for a different reason and hard-errors without it
(`GnssConfigLoadNetwork.cpp:3540-3551`).  Do not recalibrate `k`: under the exact null `k=6` is
already an α = 5.9e-9 per-cell test (§3), and on the settled window a constant would have to be
**k ≥ 14.6 to reach even α = 1e-3, and k ≥ 19.8 for 1e-4** — the latter above all but one cell in the
whole run (max `s_norm` = 19.726).  The test would be dead.

⚠ **And the fixture cannot calibrate a 6σ-class constant empirically anyway.**  9975 settled cells
resolve no rate below ≈ 1e-4; a 5.9e-9 threshold would need ~10⁸ cells, i.e. ~10⁴ of these runs.
That is the standing argument for a *derived* null over a fitted quantile — item 4's premise, and it
survives.

## 7. The open question this card does NOT close

model, uncorrelated with elevation or ionosphere?**  That is a stochastic-model / model-error
question, not a test-statistic question.  Until it is answered the per-station factor is doing double
duty as a nuisance absorber — which is exactly why R2 (declare it) is not optional.

| **spread** | **1.25×** | **2.59×** | **2.72×** |

**r_i is essentially uniform across signals (1.25×) while the residual it is supposed to explain
spans 2.59×** — and dividing by √r_i makes the signal spread slightly *worse* (2.59× → 2.72×).  The
same holds on the station axis: per-station r_i spreads **1.23×** against a z_meas spread of
**3.01×**, with corr(log z_meas, log r_i) = **−0.284** — far too weak to be the mechanism.  Over the
whole settled population r_i is remarkably flat: median **0.5114**, q01 0.0015, q99 0.6687.
Absorption would show up as low r_i on exactly those signals, and it does not.  So the heterogeneity
is **genuine misfit that varies by station and signal, on an estimator whose information distribution
is uniform**.

### 7.3 A sharper defect surfaced by the census: E[w·v²] ≠ r_i

If `v` were a correct post-fit residual under the assumed stochastic model, then $E[w_i v_i^2] = r_i$
and $z_{baarda} = |v|\sqrt{w}/\sqrt{r_i}$ would be exactly standard normal — so
$1.4826\cdot\operatorname{med}|z_{baarda}|$ should read **1.0**.  Measured, settled, above floor:

| standardization | 1.4826 · median | distance from nominal |
|---|---|---|
| `z_meas` = \|v\|√w — **the shipped one, theoretically wrong** | **1.3683** | 0.37 |
| `z_baarda` = z_meas/√r_i — **the theoretically correct one** | **1.9291** | 0.93 |

**The correct standardization lands 2.5× FURTHER from nominal than the wrong one.**  That says
$E[w v^2] \neq r_i$ on this solve, i.e. the redundancy numbers do not describe the actual residual
covariance.  Two concrete candidates: `rowRedundancy` evaluates on the **gauge-nulled free
covariance** (`NetworkEstimator.cpp:451-453`), which is not the system that produced `v` if the datum
constraints bind; or the stochastic-model error is large enough to swamp r_i entirely.  This is the
same class the in-house constraint-aware global σ̂₀ rider was written for
(`docs/SPEC_prior_residual_census.md`; formerly its own card `SPEC_sigma0_constraint_aware.md`, now
merged there), and it explains §5 cleanly: B2 measured null on the flag rate *and* pushed σ̂₀
1.246 → 1.819 precisely because it divides by a quantity that is not the residual's variance.

Incidental, and worth keeping: **the ignition ramp IS r_i.**  Median r_i runs 0.0000 → 0.0004 over
the first three assessed epochs and reaches ~0.52 by mid-run, then sits flat — the 0.836 → 1.816 rise
in `s_raw` (§4) is redundancy converging, not the residual growing.  And the floor drops only 0.49 %
of settled rows, **identically across signals** (49/10026 each), so it is not a per-signal filter.

### 7.4 `rowRedundancy` IS the right covariance — the model is what is wrong

§7.3 named two candidates for `E[w·v²] ≠ r_i`.  **The covariance is exonerated on four independent
links.**

1. **The algebra is exact** — `NetworkNormalEquations::rowRedundancy` computes
   $\mathrm{lev} = (a_s - M^\top a_r)^\top \Sigma_{ss} (a_s - M^\top a_r) + a_r^\top N_{rr}^{-1} a_r$
   with $M = N_{rr}^{-1}N_{sr}^\top$; re-deriving the arrowhead block inverse
   ($\Sigma_{sr} = -\Sigma_{ss}M^\top$, $\Sigma_{rr} = N_{rr}^{-1} + M\Sigma_{ss}M^\top$) gives
   $a^\top\Sigma a$ **identically** that expression.
2. **The datum is handled correctly** — `NetworkEstimator::solve` realizes each pin as a true
   **Dirichlet elimination** (RHS move, zero row *and* column, set the diagonal;
   `NetworkEstimator.cpp:280-292`), so `shared_cov_` is conditional *on* the datum and the row/col
   zeroing at `:444-449` only strips the artificial `1/pin_scale`.  Redundancy numbers are
   datum-invariant for estimable rows, and every row here is a row of A.
3. **The priors are in the same system** — `addStationPrior` throws if `solved_`, forcing injection
   *before* the Schur reduction, and the DD priors fold into the reduced shared normals
   (`NetworkEstimator.cpp:243-251`) before `solveSharedConstrained` fills `shared_cov_`.
4. **The residual comes from that system** — `reconstructStation` solves
   $x_r = N_{rr}^{-1}(u_r - N_{sr}^\top x_s)$ with the **same** `Nrr_ldlt` and `N_sr` the leverage uses.

Nor is the identity naive-LS-only: for a Bayesian solve with prior $\theta\sim N(\theta_0,P)$, the
prior contributions to $v = y - A\hat\theta$ cancel exactly and
$\operatorname{Cov}(v) = W^{-1} - A\Sigma A^\top$ **still holds — provided P is the true dispersion of
θ about θ₀.**  That proviso is the whole story.

**What the census measures is therefore a VARIANCE FACTOR, enormous and structured.**  With
$E[w v^2] = r_i$, the classical variance-component estimator $\hat\sigma^2 = \sum w v^2 / \sum r_i$
must read 1.0.  Settled rows with r_i > 0.01 (29 333):

| stratum | σ̂² = Σz²/Σr | σ̂ | robust med(z²/r) | mean r_i |
|---|---|---|---|---|
| **global** | **11.80** | 3.44 | 1.78 | 0.51 |
| L1C | **27.37** | 5.23 | 5.85 | 0.5151 |
| L2W | **2.05** | 1.43 | 0.80 | 0.5548 |
| L5Q | 5.87 | 2.42 | 1.70 | 0.4464 |
| S06000SIM (worst) | **61.80** | 7.86 | — | 0.4496 |
| S16000SIM (best) | **2.14** | 1.46 | — | 0.5373 |

**The variance factor spreads 13.4× across signals and 28.9× across stations while mean r_i is flat
at 0.45–0.55 (1.24×).**  That is the cleanest statement of the whole card: **r_i correctly describes
how much freedom the estimator HAS; it cannot describe how wrong the estimator's model IS, and only
the latter varies.**  L2W sits at 2.05 — nearly consistent with the assumed model — while L1C is 27×,
so whatever is mis-specified is concentrated on L1C rather than spread over the pool.  (The gap
between the aggregate 11.80 and the robust 1.78 is itself the heavy tail: the *typical* row is ~1.8×
over-dispersed, the *aggregate second moment* 11.8×.  Report both.)

### 7.5 This upgrades R1 from a heuristic to the correct estimator

§6's R1 specified a slow per-station factor fitted as a **median of cell maxima** — a heuristic,
chosen because nothing better was measurable.  The census removes that constraint.  The right
per-stratum scale is the **variance component with the redundancy in the denominator**:

$$\hat\sigma^2_{stratum} \;=\; \frac{\sum_{i\in stratum} w_i v_i^2}{\sum_{i\in stratum} r_i}$$

which is exactly what the constraint-aware global σ̂₀ rider derives globally
(`docs/SPEC_prior_residual_census.md`; formerly `SPEC_sigma0_constraint_aware.md`), now computable
**per station and per signal** because r_i is streamed.  Strictly better than the heuristic on three
counts: unbiased under the model rather than calibrated to a reference quantile; no `n_c` assumption
(the median-of-maxima reference constant disappears); and it degrades gracefully as the stratum's
redundancy changes, where a median of maxima silently conflates "quiet" with "unchecked".  ⚠ It is
also outlier-sensitive, so a production form needs a robust variant (trimmed or Huberized numerator)
— and the 11.80-vs-1.78 gap says that choice is not cosmetic.

### 7.6 The residual lives in the IONO DIRECTION — and ten candidates are dead

Decomposing the post-fit phase residual 3-vector (v_L1, v_L2, v_L5) at each (station, sat, epoch)
onto three physically meaningful directions — `(1,1,1)` (anything common in metres: clock,
troposphere, orbit, position, tides), the iono direction `(1, γ₂, γ₅)` with γ₂ = 1.6469 /
γ₅ = 1.7933, and the remaining orthogonal direction (reachable only by the per-signal
ambiguity/bias states):

| direction | share of residual variance | rms |
|---|---|---|
| common (clock / tropo / geometry) | 5.02 % | 7.7 mm |
| **iono** | **89.76 %** | **32.4 mm** |
| perp (bias/ambiguity only) | 5.22 % | 7.8 mm |

**This is the L1C answer.**  Once the common mode is removed the iono direction is
`(−0.804, +0.280, +0.525)` — **L1-dominant**, because L1 has the *smallest* iono coefficient (1 vs
1.65 / 1.79) and therefore sits furthest from the mean.  Per signal, L1C's 30.6 mm rms is 26.0 mm of
iono; L2W's 8.1 mm is 9.0 mm of iono (partly cancelling).  **L1C is not noisy — it is where
unabsorbed iono-direction error lands.**  The per-station heterogeneity is the *same* effect: the
loudest four stations are **93.2 %** iono share at 36.3 mm rms; the quietest four are **65.6 %** iono
at 8.2 mm.

**Structural corollary — the decomposition rules out an entire class by itself.**  Every
signal-independent error (satellite/receiver clock, troposphere, orbit, station position,
solid-earth tide, relativity) is identical *in metres* on all three signals and can only appear in
the common direction, which carries **5 %**.  So the culprit is necessarily frequency-dependent.
Phase wind-up (∝ λ) and the ionosphere (∝ 1/f²) both have the **wrong sign** — they load L2/L5 more
than L1.

### 7.8 ✅ MECHANISM FOUND — it is per-LOS ionosphere estimation error (+0.926)

§7.7 named the next probe: stop inferring from residuals, grade the **states** against truth.  Done,
and it closes the question.

**The instrument.**  `network.trace_ionosphere` existed but was frame-broken exactly as CLAUDE.md
warns — it emitted the reconstructed correction `x_r` alone, while the per-LOS iono state is **seeded
at allocation**, so the column was a correction, not the absolute slant ionosphere.  Fixed on the ZWD
block's own pattern (`NetworkIonoDiag.cpp`): the `iono_m` column is unchanged (pyviz consumes it) and
two columns are appended — `x_lin_m` (the seed) and **`iono_total_m` = x_lin + x_r**, the absolute
slant ionosphere.  Scale of the defect: median `iono_m` **0.95 m** against median `iono_total_m`
**8.88 m** — anyone who graded the old column was grading ~11 % of the quantity.  Trace-class, so the
gate is bit-identity: with it armed, `network_solution.csv`, `network_dd_fractional.csv`,
`network_station_residuals.csv` and `network_epoch_status.csv` are **bit-identical** to
`runs/pareref_on/logs_v2`.  Arm `runs/t3iono`, config `_simnet24_inj_t3iono.json`.

**The grade.**  Joined to `truth_atmo.csv`'s `I_L1_m` over 13 054 settled (station, sat, epoch)
triples.  The state is LUMPED (the config log: *"the receiver code delay rides inside the slant
ionosphere"*), so per standing invariant #5 the error is decomposed `e = mu + a(sta) + b(sat) + r`
and only the **interaction r** — what no receiver or satellite bias can absorb — is datum-invariant:

| term | value |
|---|---|
| raw error (lumped, NOT gradable) | mean 1.407 m, rms 3.564 m |
| overall mu | 0.328 m |
| station lump a(sta) — the receiver GF term | −3.137 … +4.156 m |
| satellite lump b(sat) | −3.116 … +4.736 m |
| **interaction r — the genuine per-LOS iono error** | **rms 0.764 m**, median\|r\| 0.142, max 9.27 |

**THE RESULT:**

$$\operatorname{corr}\bigl(\log \hat\sigma^2_{station},\; \log \mathrm{rms}\,r_{station}\bigr) \;=\; \mathbf{+0.9258}$$

The per-station iono interaction rms runs **0.106 m (S13) … 2.551 m (S06)** and orders almost exactly
with the §7.4 variance factor (S06 61.80 / S16 2.14).  The contrast is decisive: the **lumped** term
correlates **−0.103** — so it is *not* the receiver code-bias partition, and not any bias the datum
can move.  It is the per-line-of-sight ionosphere estimate being wrong, by up to 2.5 m rms at the
worst station.

### 7.8.1 The causal chain, and one correction to it

| step | measured |
|---|---|
| per-LOS slant iono state error (datum-free interaction) | rms **0.817 m** |
| absorbed by the collinear per-arc **ambiguity** | ~96 % |
| unabsorbed remainder → phase residual, iono direction | rms **0.033 m** |
| corr(iono error **level**, residual iono coefficient) | **+0.532** |
| corr(iono error **change**, residual iono coefficient) | **+0.046** |

⚠ **The residual tracks the iono error's LEVEL, not its rate of change.**  The natural guess — that
the ambiguity soaks up the constant part so only the time-variation shows — is **wrong**: the change
correlation is null.  The ambiguity absorbs ~96 % of the level and the unabsorbed ~4 % passes through
proportionally.

That closes every open thread in §7.7: the effect is universal (every station has iono error), stable
in time (the error level is persistent per arc), independent of elevation and arc age, invisible to
`r_i` (the *geometry* is uniform; the *iono fit* is not), unmoved by multipath, and L1-dominant
because the iono direction is L1-dominant once the common mode is removed (§7.6).

### 7.8.2 Two consequences beyond this card

1. **R2 is now non-negotiable.**  A per-station variance component would bury a measured
   **0.11–2.55 m per-station ionosphere estimation error** inside the noise model.  That is no longer
   a stylistic worry — it names the quantity that would be hidden.
2. **This is very likely the same root as the integer-resolution failure.**  The ambiguities are
   absorbing ~96 % of a 0.8 m iono error; an ambiguity biased by that cannot be fixed to an integer.
   The project's standing finding is `project_why_non_integer_rootcause` — *"NL 99.3 % iono"* — and
   the AGU-26 amendment records AR fix rate 0 % with med\|frac_cyc\| uniform at 0.25.  §7.8 supplies
   the truth-graded number behind both.  ⚠ Asserted as a connection, not measured here — see §7.9,
   which then measured it.

### 7.9 ✅ The DD-integer tie — MEASURED, and the sensitivity ladder holds

**The prediction.**  For phase on signal j, `φ_j = ρ + T − γ_j·I_L1 + λ_j·N_j`.  An iono error
`d = Î − I_true` must be absorbed by the ambiguity:

$$\lambda_j\,(\hat N_j - N_j^{true}) = \gamma_j\, d \quad\Longrightarrow\quad e_j = \frac{\gamma_j}{\lambda_j}\, d$$

In DD form the station and satellite main effects cancel exactly, so the driver is the double
difference of the §7.8 interaction term.  The resulting per-band sensitivities — **L1C 5.255,
L2W 6.744, L5Q 7.037 cyc/m** — reproduce the ladder `scripts/simnet_amb_integer.py` already documents
(*"L1 5.26 cyc, WL 1.49, EWL 0.29"*), and the lane values fall out as **differences**:
WL(1,2) = 5.255 − 6.744 = **−1.489**, EWL(2,5) = 6.744 − 7.037 = **−0.293**.  ⚠ The documented
figures are magnitudes; the **sign is negative** for both lanes.

**The measurement.**  DD integer error `e = dd_cyc − DD_true` from `network_dd_fractional.csv` joined

**The per-band DD ambiguity error is 68–83 % accounted for by the truth-graded per-LOS ionosphere

## 12. Field check — the structure reproduces, the remedy's leverage does not

Run on `net_matrix_2024-129/net50_1h` (DOY-129 **real data**, 49 stations, GPS+Galileo, 115 epochs,
76 099 cells) from the 2026-08-12 archive.

⚠ **Provenance and scope.**  These are archived pre-VS2026 runs that CLAUDE.md flags as not trusted
for accuracy — *regenerate rather than re-grade*.  Nothing here is an accuracy verdict.  What is read
is the **structure of the residual population**, a property of the trace itself.  ⚠ And the field has
**no truth**, so its 27.3 % flag rate is **not** a false-alarm rate: an unknown share is real slips.
That asymmetry is exactly why the derivation fits on the sim.

**The structural claim generalizes, and gets stronger:**

| | sim (`pareref_on`, 24 sta) | field (`net50_1h`, 49 sta) |
|---|---|---|
| station scale spread | 4.7× | **10.5×** |
| corr(log station scale, half 1 vs 2) | +0.847 (23 sta) | **+0.873 (49 sta)** |
| per-satellite scale spread | — | 6.0× |

**But the remedy's leverage collapses:**

| scoring | sim | field |
|---|---|---|
| as shipped, held-out half | 4.4625 % | **27.58 %** |
| ÷ OOS scale(station × epoch) | **0.9736 %** (4.6×) | **18.48 %** (only **1.5×**) |
| implied c, k=3 → k=10, after stratification | 1.97 → 2.39 | **3.07 → 6.02** (still steep) |

### 12.1 Why — the σ̂₀ floor binds on the field, and that voids §2's premise

| run | σ̂₀ median | epochs **pinned at the 1.0 floor** |
|---|---|---|
| sim `pareref_on` (24 sta) | 1.247 | 38/114 = 33 % |
| field `net50_1h` (49 sta) | **1.0000** | **110/115 = 95.7 %** |
| field `h3_guard` (305 sta) | **1.0000** | **312/354 = 88.1 %** |

**On the field the denominator is a constant almost all the time.**  §2's invariance theorem holds
only while the floor is *not* binding; when it binds, $S_c$ degenerates to the bare
$\max_{i\in c}|z_i|$ compared against a fixed 6σ bar — no normalization at all.  Stratifying the pool
cannot buy much when the statistic is discarding the pool's scale by clamp.  **The field runs almost
entirely in the regime the sim barely visits.**

**Why the field pool sits below the floor is an OPEN question, and the obvious answer is contradicted
by the configs.**  The tempting explanation is redundancy shrinkage ($E[w_i v_i^2] = r_i < 1$, so
$1.4826\cdot\operatorname{med}|v|\sqrt{w}$ lands under 1 and the missing $\sqrt{r_i}$ pushes it under
the clamp).  But **the field posture assumes `phase_std_m = 0.002 m`, SMALLER than the sim's 0.003**
(both `stochastic_model: elevation`), which pushes $|v|\sqrt{w}$ *up*, not down.  Inverting the two σ̂₀
values gives the elevation-scaled post-fit phase misfit:

$$\operatorname{med}(|v|/f) \;\approx\; 1.35\ \text{mm (field)} \quad\text{vs}\quad 2.52\ \text{mm (sim)}$$

**The sim's post-fit phase residuals are ~1.9× LARGER than real DOY-129 data's**, on the same
estimator.  So the field is not "noisier and clamped"; the *sim* is the loud one, and the clamp is what
a well-behaved pool looks like under this floor.  Redundancy shrinkage, a genuinely quieter field
posture, or an unrealistically noisy sim (§7 lead 1) — unresolved, and now the sharpest question in the
card, because the answer decides whether "unclamp the field" or "quiet the sim" is the next move.

### 12.1b ⚠ At 305 stations the remedy stops working — and the reason is drift

`pdp305_pinaware/h3_guard` (DOY-129 field, **303 stations present**, 354 epochs, 1 016 566 cells,
806 794 settled over 293 epochs).  The leverage trend across all three arms:

| | sim 24-sta | field 49-sta | **field 303-sta** |
|---|---|---|---|
| station scale spread | 4.7× | 10.5× | 7.1× |
| corr(log scale, half 1 vs 2) | +0.847 | +0.873 | **+0.782** |
| as shipped, held-out half | 4.46 % | 27.58 % | 9.57 % |
| ÷ OOS scale(station) | — | — | **10.31 % — WORSE than shipped** |
| ÷ OOS scale(station × epoch) | **0.97 %** | 18.48 % | **8.42 %** |
| net leverage | **4.6×** | 1.5× | **1.14×** |
| implied c, k=3 → k=10, after stratification | 1.97 → 2.39 | 3.07 → 6.02 | **2.55 → 4.78** |

**Out-of-sample station stratification makes the 305-station arm WORSE** (9.57 % → 10.31 %); adding
the fast epoch factor recovers it only to 8.42 %, a 1.14× net win, and the implied-c curve is
essentially unmoved (2.68 → 4.79 shipped vs 2.55 → 4.78 stratified).

**The mechanism is drift, visible in the transferability column.**  The station factor's
half-to-half correlation *falls* with window length: +0.847 (1 h sim), +0.873 (1 h field), **+0.782
(3 h field)** — not a sample-size effect, since each 305-station half carries ~1300 cells per station
against the 24-station arm's ~200.  **The per-station scale is not stationary over 3 h on real
data.**  A factor fitted on the first half is stale by the second, and applying a stale scale is
worse than applying none.

⚠ **This qualifies R1's premise directly.**  §4.1's "+0.847, STABLE, transferable" was measured on a
1-hour window and does not survive extension.  The slow factor must therefore **track** — an EWMA
with a real time constant — rather than be fitted once, and **that time constant is unmeasured**.
§6's slow/fast split survives (it is forced by the noise budget); what does not survive is the
assumption that "slow" can mean "constant over the run".

⚠ **Instrument limitation, found here:** `scripts/t3_null_fit.py` is pure-Python by design and
**timed out after 50 minutes** on this run's 1 M cells; the numbers above come from a numpy
re-implementation of the same decomposition.  A field-scale run is exactly where the tool matters, so
this is a defect in the tool, not in the fixture.

### 12.2 ⚠ This BOUNDS the §5 falsification — reopen B2 for the field

§5 measured `raim_redundancy_normalize` as a null **on the sim, where the floor rarely binds**.  On
the field it would lift the pool by ≈ ×1.45 and **unpin σ̂₀ on most epochs** — not a rescaling that
cancels but a change of *regime*.  The sim result therefore **does not transfer**, and B5's "do not
arm it" must be read as sim-scoped.  A field B2 arm is now an owed measurement, not a closed question.

### 12.3 Falsified in passing

with flag rates 27.23 % vs 27.48 %.  A GPS/Galileo mixture is *not* a third heterogeneity axis.

**max 38 934.8**, with 312 cells (0.66 %) above 100 and **40 above 1000**.  The sim null arm's max is

## 14. The 305-station trace smoke — it found a defect, not a cost

Two 20-epoch runs at 305 stations (GPS+Galileo, `_golden0729` lineage: `carry_invariant` + eq34 +
SH), configs `_t3trace305_20ep_smoke{,2}.json`, arms `runs/t3trace305_smoke{,2}`.  Purpose was to

NOT a grading run: 20 epochs is 10 minutes and sits entirely inside ignition, where r_i ramps
0.0000 → ~0.52 (§7.4) — no flag rate, variance factor or iono error may be read off it.

### 14.1 Round 1 — post-fit RAIM screened NOTHING while the loader logged "ENABLED"

`EXIT=0`, 20/20 epochs emitted, and:

```
T3,post-fit RAIM cell (T3),0,0,0.000000e+00
network_raim_redundancy.csv      0 rows   (header only)
network_station_residuals.csv    0 rows   (header only)
```

**Mechanism.**  `ApplicationNetworkAssembly.cpp:2603-2605` gates the RAIM pool fill on

```cpp
const bool do_amb_carry = (phase_datum_prioritized || !st.is_pivot) && !carry_invariant;
```

so under `carry_invariant` **`R.pl_amb` is empty for every station**, `ambPool()` hands
`networkPostFitRaim` an empty pool, and `if (pool.empty()) continue;` skips all 305.  `phase_leveling`
does **not** rescue it — it satisfies the `carry_warm` CALL-SITE gate only.  The alternative pool
`qc_amb` is filled solely under `raim_carry_invariant`, which this lineage does not arm.

**And the loader's guard ladder had a hole that hid it.**  `GnssConfigLoadNetwork.cpp` opened with

```cpp
if (network_phase_leveling_ && !network_raim_carry_invariant_)   //  ← took this branch
    log->info("... post-fit RAIM ... ENABLED ...");
else if (network_raim_carry_invariant_) ...
else if (network_carry_invariant_)      log->warn("... INERT ... screens NOTHING ...");
```

With `phase_leveling` **and** `carry_invariant` both on, the run takes the *first* branch and the
INERT warning is unreachable — exactly the configuration where it is needed.  **Fixed**:
`!network_carry_invariant_` added to the first branch, and the carry_invariant warning rewritten to
name the pool as the prerequisite and to say explicitly that phase_leveling does not rescue it.

This is the "reports ARMED and screens NOTHING" class (standing invariant #4) *inside the ladder
built to catch it*.  The loader already carries a comment 400 lines earlier saying the same lesson
was applied to the `carry_vce_apply` family "before the run instead of after it … that costs a whole
field run to learn".  Here it cost 32 minutes instead of a field run.
