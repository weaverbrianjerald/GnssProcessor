## 6. The five decisions of UOM section 7, answered (2026-10-31)

1. **`ISlipDetector`.** Not done. On main the interface survives with five virtuals (`detect`, `resetSatellite`, `resetSatelliteSignal`, `kind`, `name`), the documented no-op `setCorrections` and `asMelbourneWubbena`; three detectors implement it (MW, GRAPHIC, EWL); the kinds `GeometryFree` and `IonoFreePhase` are named and never created; one caller dispatches `detect` (`CycleSlipManager`); the set is listed in four places (the kind enum, `toString`, the creator table, the selection list) beside the configuration token. Recommendation: keep the three detector classes, delete no virtual, and fold the four lists into one declared row per kind (kind, token, toggle, creator) in `SlipDetectorRegistry.cpp`; size S; a new user-side detector is not planned, so the table can wait for the next detector.
2. **Network-only code in user classes.** Largely moot after N6. `MeasurementModelNetwork.cpp` (245 lines at `ff7766a`) was deleted when a station's parameters moved to its own parameter set, `MwPhaseBridge.cpp` (287 lines) by card RKD, and a network station no longer holds a `StateManager` or `MeasurementModel`. Recommendation: no banner or translation-unit split pass; move the IF detector to `network/slip/` when card NOM next edits it, and leave the rest, since the owner question is settled by the parameter set.
3. **Order of the behaviour changes.** Done in part: UB1 landed with the wave, UB2 landed on main (`1902e62`), UB3 is built here on its own branch. Recommendation: adopt UB3, G9, G10, UB6 and UB7 (none moves a golden number); then UB4 with the next edit of the reset; UB5 next, through the ledger and gated as a change of the goldens' numbers (the one step with a counted defect on the consumer's path; UB9 reaches the consumer too, uncounted).
