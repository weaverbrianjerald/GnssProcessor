# GnssProcessor vs NGS M-PAGES: Cycle-Slip Methods Comparison

Code-grounded comparison of cycle-slip detection, repair and residual-feedback handling. References are `file:line` against the two trees; M-PAGES paths are under `reference_software/mpages/M-PAGES/`. (Moved from the repo root to `docs/` 2026-08-14; filename unchanged. Section numbers §3.1–§3.5 are stable — other slip docs and the `reference_mpages_codebase` memory card summarize by dimension.)

## 1. Verdict

**The two systems are built around fundamentally different processing models, and that difference — not threshold cleverness — drives most of the verdicts.** M-PAGES decides slips entirely **pre-solve and offline** in a standalone batch editor (`DbEdit`) whose outputs are inspectable text artifacts; GnssProcessor folds slip handling into a **recursive, real-time-capable Kalman estimator** with a genuine closed post-fit residual loop.

| # | Dimension | Verdict | Qualifier |
|---|---|---|---|
| 1 | Post-fit residual evaluation (§3.3) | **CONFIRMED, decisively and code-verified** | GnssProcessor is the only one with an in-loop solution-residual feedback path; M-PAGES has no KF and its one true post-fit pass is diagnostic-only (`SdEngine.cpp:4327-4341`). The honesty caveat in §3.3 is load-bearing and understated in any headline. |
| 2 | Pre-processing detection (§3.1) | **ONLY PARTLY CONFIRMED** | GnssProcessor's MW gate is materially more sophisticated (robust MAD, cross-sat cold-start breadth, EWMA, elevation-shaping), but M-PAGES's WL and ion-free triggers are already adaptive (per-arc running RMS) ⇒ the steady-state margin is **incremental on two of three triggers**. Only its fixed 1.0-cy geometry-free threshold is a clear weakness. GnssProcessor wins *categorically* at cold start, low rate, multi-GNSS/multi-frequency breadth and continuity preservation — **not** on raw threshold adaptivity. |
| 3 | Repair / integer fixing (§3.2) | **SPLIT** | GnssProcessor wins on repair capability, rejection correctness and real-time applicability; M-PAGES has the cleaner batch jump kernel, a coherent detect-and-break → AR strategy, and a safer *validated* default. |
| 4 | Pivot / ref-sat handling (§3.4) | **AHEAD IN CAPABILITY, BEHIND IN BATTLE-TESTEDNESS** | — |
| 5 | Coverage (§3.5) | **GnssProcessor wins nearly every axis** | Two caveats cut against the breadth narrative: the missing clock-jump pre-editor, and RT slip-body duplication. |

**Fit-for-purpose framing.** For **offline NGS-style network/baseline production**, M-PAGES's model is arguably the better fit: clean separation of concerns, inspectable artifacts, non-causal two-sided jump estimation, a dedicated clock-jump editor, and a conservative validated default that never mis-fixes. For a **unified precise-nav engine spanning streaming and post-processing**, GnssProcessor is clearly ahead. **This is not a "better/worse" axis.**

## 2. Architectural contrast

| Axis | M-PAGES | GnssProcessor |
|---|---|---|
| Processing model | Batch, offline, edit-then-solve | Recursive KF, real-time **+** post-processing, same kernel |
| Slip decision locus | Pre-solve only, in `DbEdit` (`DbEdit.cpp:356-385`) | Two coupled stages: pre-fit MW/TurboEdit **and** in-loop KF post-fit |
| Causality | Non-causal (symmetric ± windows, `fitGap`) | Causal/online; post-proc revisits only via RTS smoother (no residual test) |
| Stage coupling | Single-purpose executables, **no shared in-memory state**; text artifacts (`.arc/.brk/.amb/.sum`) | Live KF/StateManager/pivot/smoother state interlocked |
| Estimator | Batch normal equations, ≤5-iter relinearization (`SdEngine.cpp:2283-2300`) | Joseph KF with measurement-rebuild loop |
| Extension seam | Edit `DbEdit`'s hard-coded combo set | `ISlipDetector` registry (`SlipDetectorRegistry.cpp:54-72`) — partly aspirational (GF staged-uncompiled; RT bypasses it) |
| Integer recovery | Defer to break + dedicated AR stage (`Lib/AmbRes`) | In-line covariance-preserving additive repair |

M-PAGES is a textbook separation-of-concerns chain: `Rnx2Db` ingest → `DbEdit` slip edit → `ArcInfo` arc geometry → `SdSolve/DdSolve` adjust → `AmbRes` integer fixing. Each stage's interface is a human-readable file, so the editor can be re-run with new parameters and the solver re-run unchanged — exactly what a mature NGS batch product wants for auditability and piecewise reprocessing. GnssProcessor trades that decoupling for capability M-PAGES structurally cannot reach: one estimator/repair kernel in streaming *and* batch, a closed loop on post-fit residuals, and arc continuity preserved through repairs. The honest cost is much higher coupling and statefulness, and **no inspectable per-stage artifact equivalent to `.arc/.brk/.amb/.sum`**.

## 3. Dimension-by-dimension

### 3.1 Detection statistics & thresholds

**M-PAGES.** `DbEdit::findSlipLocation` (`DbEdit.cpp:809-869`) ORs three single-differenced, time-differenced combos: a geometry-free `ION_RESID = φ1 − (f1/f2)·φ2` (`DbEdit.cpp:514`, verified) with a **fixed** `ion_res_threshold` (default 1.0 cy, shared across all sats/elevations); a Melbourne-Wübbena wide-lane and an ion-free combo, both with **adaptive** thresholds `rms_scale_factor × rms[sat][·]` (default 5σ). The per-arc RMS is Welford-accumulated **only inside fixed sanity windows** (`|ION_SD|<0.5, |WL_SD|<10, |IF_SD|<0.5`, `DbEdit.cpp:706-735`) so slips don't poison the floor. Flags are gated within `max_gap_seconds` (120 s) and a consensus ref-sat check reattributes all-sats-flagged events (`findRefSatSlips`, `DbEdit.cpp:1126-1170`). Dual-frequency only; multi-GNSS via per-constellation serial runs.

**GnssProcessor.** `MwSlipDetector` gates on a **100 % empirical** threshold with no stochastic-model σ floor on any trigger (`MwSlipDetector.cpp:853-873`). Mature regime (window ≥15) returns `σ_mult × max(per-arc MAD, 0.01 m)`; cross-sat σ is deliberately *not* applied as a mature floor. Warmup uses a 3-tier EWMA-blended cross-sat MAD cascade (band-pair → constellation → global-non-GLONASS, `MwSlipDetector.cpp:742-847`) re-expanded to arc elevation via a `1/sin(el)` **shape**, GLONASS excluded from the global tier. Deviation and gate-spread are always the *same* statistic, eliminating the trend-lagged-level-vs-collapsed-MAD false-slip mode. `TurboEditResolver` adds a rate-adaptive MW+GF 2×2 solve; auxiliary GRAPHIC/EWL detectors add MAD cross-checks. **GF is staged-uncompiled** — `src/core/slip/GfSlipDetector.cpp` is commented out of the `gnss_core` slip list at `CMakeLists.txt:126` (the anchor the pre-merge text gave as `CMakeLists.txt:99-116` before the list grew). ⚠ **IF-phase is NO LONGER staged-uncompiled**: `IfPhaseSlipDetector.cpp` builds at `CMakeLists.txt:125` and is active on the **NETWORK** path (`network.cycle_slip.if_phase_td`); it remains staged for user/kinematic only.

**Verdict.** GnssProcessor is more sophisticated in the steady state, **but the margin is incremental, not categorical**: M-PAGES's WL and IF triggers are already adaptive, so the real delta is robust MAD (vs RMS), cross-sat cold-start breadth, EWMA and elevation-shaping — genuine refinements over an adaptive baseline. Only the fixed-1.0-cy geometry-free trigger is a clear M-PAGES weakness. **GnssProcessor wins clearly on**: cold-start statistical strength (a 9-dof MAD from 10 GPS sats at epoch 2, where per-arc RMS has essentially no information), false-alarm / missed-detection trade-off across receiver classes, low-rate handling, and multi-GNSS / multi-frequency breadth. **M-PAGES wins on**: simplicity/auditability (its detection reads in a page; GnssProcessor's spans warmup/mature/cold-start branches + a 3-tier cascade + a separate TurboEdit cascade), determinism, and non-causal estimation. **Neither** has a formal hypothesis test (no DIA/w-test/χ²). One under-surfaced GnssProcessor cost: the layered adaptivity carries concrete failure modes the fixed thresholds do not — **cross-sat pool contamination and EWMA lag during abrupt environment change** — and **GLONASS cold start drops straight to the coarse `min(λ_WL, 1 m)` gross gate** (`MwSlipDetector.cpp:937-947`), narrowing the advantage for GLONASS specifically.

### 3.2 Repair / integer fixing

**M-PAGES.** `findSlipSize` (`DbEdit.cpp:872-969`) is a batch, non-causal, two-combo closed-form solve. `fitGap` fits a low-order LS polynomial with a step-indicator over **symmetric pre- and post-slip windows** (`DbEdit.cpp:971-1033`), yielding two jumps that invert to per-frequency floats. Accept gate (`DbEdit.cpp:933`): data on both sides **and** both fractional distances `< cs_fix_fraction_limit` **and** not a ref-sat slip; the fix uses C-style truncation `(int)(x)` (verified `DbEdit.cpp:929-935`). **Critically, `cs_fix_fraction_limit` defaults to 0.0 with strict `<`, so the shipped configuration NEVER FIXES ANY SLIP** — every detected slip becomes an arc break and integer recovery is deferred to the dedicated AR stage (`Lib/AmbRes`: MLAMBDA / bootstrap / round / partial with ratio gating). The benchmark confirms it: `okan1440.sum` shows `totalSlips:2 fixedSlips:0`.

**GnssProcessor.** `TurboEditResolver::resolve` single-sources `dN_wl` from `MwSlipDetector` and pairs it with its own GF second-difference TD2; the 2×2 solve (`TurboEditResolver.cpp:1310-1313`) rounds **to nearest** (`std::llround`), accepts on `frac2 ≤ 0.30`, and stages per-signal repairs applied as covariance-preserving additive shifts `x += dN·λ` (`RealTimeEngine.cpp:1073-1105`). It explicitly closes MW's `dN1=dN2` blind spot via a GF-only path requiring affirmative `mw_clean_pairs` evidence (`TurboEditResolver.cpp:1177-1188`), a rate-adaptive `splitCapable()` gate (`:214-222`), and a gap-spanning GF bridge (`:850-1169`).

**Verdict.** On integer-solve *mathematics* the two are near-identical and **M-PAGES is the cleaner reference**: its non-causal both-sides polynomial step-fit detrends iono/geometry and gives a more robust jump than GnssProcessor's single causal TD2 second-difference, which is noisier and lattice-degenerate at low rate. Three things separate them. **(1) Default posture:** M-PAGES ships *break-everything* — a deliberate, validated NGS reliability choice that structurally cannot mint a wrong integer; GnssProcessor repairs by default with continuity-preserving shifts, the more capable behavior *when correct*. **The entire "repairs by default vs never fixes" axis turns on a single config knob NGS leaves at 0 BY POLICY — capability presence is not the same as validated behavior.** **(2) Blind-spot coverage:** GnssProcessor explicitly handles equal slips at repair time; M-PAGES detects them (see the §4 correction) but with default config just breaks. **(3) Rejection handling:** GnssProcessor's reject cascade is far richer (code-event veto, conflict→reset, WL-settle deferral). The genuine M-PAGES truncation flaw is the **toward-zero magnitude bias when a fix IS accepted** — not rejection behavior, which is moot at the default limit. GnssProcessor's repair correctness is **conditional on cross-module evidence** (`dN_wl` + `getEpochCleanPairs` + gap evidence); a defect in any silently degrades repair. The historical `(−9,−35)` vs truth `(0,−28)` event (`TurboEditResolver.cpp:1095-1106`) was the **motivating case that prompted the WL-settle deferral** — present code defers rather than guessing in that ambiguous configuration; it is **MITIGATED, not a standing failure**.

### 3.3 Post-fit residual evaluation / outlier feedback

**M-PAGES.** No closed post-fit feedback loop anywhere. `DbEdit` is a pre-solve editor with no estimator. `SdEngine/DdEngine` *do* compute true post-fit residuals and RMS/WRMS (`SdEngine.cpp:2656-2779`), but the only editor that affects the solution is **prefit** (prior-iteration-relinearized O−C, gated `!PostFitRun && IterCount>1`, `SdEngine.cpp:3861-3958`), and the one true post-fit pass merely re-applies stored `OutlierMap` NaNs (`SdEngine.cpp:4327-4341`) — it detects nothing new and does not iterate. The intended cross-sat bootstrap consistency test is dead/forced-false (`SdEngine.cpp:3970,4024,4031`). No χ², no w-test, no IRLS.

**GnssProcessor.** A genuine closed in-epoch loop in `KalmanFilter::update`: after the Joseph update it computes `r = innov − H·dx` and the theoretically correct `Sr = R − H·P_post·Hᵀ` (`KalmanFilter.cpp:893-911`), standardizes `sres = r/√max(Sr, R, 1e-12)` with the **R-floor that defeats the DD/BSSD phase-absorption collapse** (`:944-976`), then dispatches by signal: phase outlier → ambiguity reset (pivot frozen); code → row exclusion; sub-cycle → exclude; too-many → full reset. The update is **held uncommitted** and returns `NeedsMeasurementRebuild`; the driver (`Application.cpp:761-857`) re-forms measurements, forwards pivot handovers, scrubs MW/TurboEdit arc history, reinflates iono/sat-bias variance, and re-runs until a clean commit. Robust MAD/median group detectors (`:1807-2194`) escalate coherent pivot disturbances to forced handover. Reset/handover boundaries segment the RTS smoother.

**Verdict. Decisive, code-verified GnssProcessor win on this dimension** — a real closed post-fit (solution-residual) loop that M-PAGES structurally lacks, plus a genuine numerical-correctness contribution in the `Sr→R` floor. **But the honesty caveat is load-bearing and is *understated in the headline*:** the gate is a **fixed `|sres| > 6σ` per-row threshold** plus heuristic MAD group tests — **no DIA, no χ², no Mahalanobis innovation gate, no redundancy/MDB**. GnssProcessor's post-fit threshold is in fact **LESS adaptive than its own MW pre-filter and than M-PAGES's adaptive WL/IF RMS gates**. Accurate statement: GnssProcessor uniquely *has* the loop and standardizes it correctly; it does **not** have statistical rigor, and **neither system implements classical geodetic reliability theory**. Additional honest gaps: the loop is **greedy one-outlier-per-pass** (not a joint multi-outlier estimator); it is **causal-only** (the smoother does no residual testing — `Smoother.cpp:33-44` — so there is no non-causal second pass); the temporal EWMA corroboration is **diagnostic-only and off by default**; and phase "repair" here is a **float re-seed + variance inflation (arc restart), NOT integer continuation** — integer repair lives only in the pre-fit layer. M-PAGES's prefit editor, by contrast, is batch/non-causal and estimate-aware *across iterations*, and propagates full SD/DD covariance (`NgsLsq.cpp:158-188`).

### 3.4 Reference-satellite / pivot slip handling

**M-PAGES.** Reference = per-epoch max-elevation SV (`DbEdit.cpp:610-635`). `findRefSatSlips` (`:1126-1181`) triggers only in the degenerate all-or-nothing case (`slipCount == svCount`), reattributes to the ref sat, and **forbids integer-fixing it** (`refSatSlip` gate, `:891-894`) — forcing a clean break of all arcs. Ion-free detection is correctly suppressed at ref-sat *changes* (`:838-841`). Downstream re-anchors a new ref-sat ambiguity with a 0.001 m constraint (`SdEngine.cpp:5921-5928`).

**GnssProcessor.** Two independent pivots (MW pivot re-referenced to ZD per sat, `MwSlipDetector.cpp:2526-2613`; KF/BSSD pivot frozen at SD 0). On a pivot slip the **preferred path preserves continuity**: in-place relative repair `rel = dN_peer − dN_pivot` with covariance preserved, **plus a subtle `−dN_pivot` shift of confidently-clean *non-slipped* peers because the frozen reference moved under them** (`CycleSlipManager.cpp:1338-1397`) — a case M-PAGES has no analog for. Fallback forced handover builds a **consensus exclude set** spanning all detector levels (`:1514-1522`) so the replacement pivot is never mid-slip, with a retired-pivot backstop (`handoverFired()`, `:1540-1561`). KF spatial-coherence MAD detectors provide an independent post-fit backstop.

**Verdict. GnssProcessor is materially more capable and more continuity-preserving here** — clearly ahead in design. **But the maturity/correctness gap is *larger* than a "clear win" implies**: M-PAGES's rule is ~55 production-hardened lines that essentially cannot mis-repair a ref-sat slip, whereas GnssProcessor's pivot path is **hundreds of lines with a documented bug history — handover flip-flop, BSSD pivot-handover frame pitfall, code-only pivot iono-scrub gap, *per the user's own memory*** — plus **a `const_cast` write seam** (`:1493-1494`) and a **one-epoch-late backstop dependency**. M-PAGES's batch consensus also uses full forward+backward arc context, a cleaner signal than GnssProcessor's causal, one-epoch-lagged cross-sat evidence for a *pure* ref-sat slip. **So: ahead in capability and continuity, BEHIND in battle-testedness for the routine it surpasses.**

### 3.5 Multi-GNSS / multi-frequency / real-time coverage

**M-PAGES.** Batch, offline, **DUAL-FREQUENCY ONLY** (`DbEdit.cpp:504-530`; `Rnx2Db` `MIN_FREQS=2`), **PER-CONSTELLATION SERIAL** (`DbEdit.cpp:211-235`, OpenMP commented out). 30 s low-rate is the design centre, well-served by the non-causal `fitGap` both-sides fit. **LLI is READ BUT DISCARDED** (`RinexObs.cpp:1996-2001` parsed; never consumed in `Rnx2Db.cpp:801-875`). A **dedicated `RepairClockJumps` pre-editor** (median+MAD, three ms-artifact classes, deterministic integer-ms corrections, `RepairClockJumps.cpp:168-215, 290-325, 357-387`; auto-disabled sub-second) runs **before** slip detection. No streaming path.

**GnssProcessor.** Same kernel in batch and real-time. Constellation-generic cross-sat MAD cascade with GLONASS/FDMA special-casing; native N-frequency including EWL (`EwlSlipDetector.hpp:5-16`) with culprit isolation across 3+ pairs (`CycleSlipManager.cpp:399-446`). Rate-adaptive gates degrade gracefully to coarse cadence. **LLI is AUTHORITATIVE** (`CycleSlipManager.cpp:706-711`), with `SoftLliBridge` holding AR-capable ambiguities across short gaps (`SoftLliBridge.cpp:195-232`), shared PP/RT. First-class streaming repair (`RealTimeEngine.cpp:1005-1244`).

**Verdict. GnssProcessor wins on nearly every axis this dimension names** — constellation breadth, multi-frequency, real-time, authoritative LLI — **but the comparison is partly apples-to-oranges** (an N-freq N-GNSS streaming engine vs a hardened dual-freq batch tool). Two caveats cut against the breadth narrative and are **not reflected in the higher-level verdict**: **(1) `RepairClockJumps` is a targeted capability GnssProcessor GENUINELY LACKS** — it folds clock anomalies into the generic KF code-outlier path, which is reactive and per-row, not a deterministic median+MAD ms-jump editor applied uniformly pre-estimation; **a real functional gap**. **(2) The RT path DUPLICATES the slip-orchestration body inline** rather than calling `CycleSlipManager::detectAndRepair`, so the in-place pivot-relative machinery (`:1247-1621`) is not obviously mirrored in RT — **a divergence risk M-PAGES (one batch path) does not have**.

## 4. Gap index

**Where GnssProcessor is stronger** — all argued in §3, listed here as pointers: closed post-fit residual feedback loop (§3.3, the single clearest fully-verified win; `KalmanFilter.cpp:893-1014`, `Application.cpp:761-857`); the `Sr→R` standardization floor (§3.3, `KalmanFilter.cpp:944-976`); continuity-preserving pivot repair (§3.4, `CycleSlipManager.cpp:1291-1397`); real-time streaming repair on the same kernel (§3.5, `RealTimeEngine.cpp:1005-1244`); native multi-frequency / multi-GNSS (§3.5); authoritative LLI + `SoftLliBridge.cpp:195-232` soft-LLI gap bridge (§3.5); cold-start statistical strength (§3.1, `MwSlipDetector.cpp:742-847`). **Where M-PAGES is stronger / GnssProcessor has gaps** — pointers plus the facts that appear ONLY here:

- **Non-causal two-sided jump estimation (`fitGap`, `DbEdit.cpp:971-1033`)** — for the stated offline-NGS use case, arguably the *single most important quality axis*, and **GnssProcessor structurally cannot match it even in post-processing mode**: its repair jump is a causal TD2 second-difference and its RTS smoother does **no** residual testing or slip detection (`Smoother.cpp:33-44`). This is the provenance of the non-causal slip-bridge card — see **`docs/SPEC_noncausal_slip_bridge.md`** (§15 for the `fitGap` provenance and the do-NOT-copy warning on `DbEdit.cpp:925-926`).
- **The `RepairClockJumps` gap (§3.5)** — a real functional gap, not a stylistic one.
- **Inspectable, independently-reproducible per-stage artifacts** (`.arc/.brk/.amb/.sum` + per-slip CSV with window indices, fit-point counts, fitted jumps, float/integer pairs; `DbEdit.cpp:782-806`). GnssProcessor's slip provenance lives in optional trace rows entangled with live KF state — **you cannot re-run "just the editor" against a fixed downstream solver.**
- **Conservative break-never-wrong-fix default is the *validated* behavior** (`okan1440.sum`: `fixedSlips:0`). It structurally cannot mint a wrong integer; GnssProcessor's by-default additive repair is correct only when the (cross-module-evidence-dependent) integer is correct.
- **Coherent end-to-end integer strategy**: detect-and-break in `DbEdit` → re-fix in a dedicated AR stage (`Lib/AmbRes`, MLAMBDA/bootstrap/partial with ratio gating) — **not "no repair," but a different, defensible division of labor.**
- **Production maturity & benchmarking** — reference solutions in `Tests/SUITE_TESTS/`.
- **Auditability and lower failure-mode surface** (§3.1, §3.4).

**CORRECTION OF A RECURRING FRAMING — M-PAGES is NOT blind to `dN1=dN2` equal slips** and does not depend on the ion-free combo for them: its plain geometry-free `ION_RESID` responds as **`≈−0.28N` cy** (verified `DbEdit.cpp:514`), so it detects equal slips even in geometry-free-only (SA-legacy) mode. With default config it just breaks.

**STALE-CLAIM RETRACTION.** The repeated "the slip chain has zero tests" framing **is stale and is dropped here** — `test_turbo_edit_resolver.cpp` and `test_soft_lli_bridge.cpp` are compiled and registered. (Scale note added 2026-08-14: this doc and the attic slip audit were written in the ~190-test era; the suite is now 1360 cases / 196 suites / 89 files, re-counted 2026-08-12, and `test_turbo_edit_resolver.cpp` now carries **35** cases, `test_soft_lli_bridge.cpp` **6** — the "21 cases" figure originally quoted here is superseded. `docs/attic/slip_repair_audit_2026-06-10.md` Pass-2 still carries the opposite "zero tests" claim; **this retraction is the later and correct one.**) **SELF-DISCOUNTING NOTE.** Several GnssProcessor advantages cited above rest on features the user's own memory flags as **uncommitted and not-yet-data-validated** (real-time GLONASS/SSR, slip-audit fixes, BSSD pivot fixes); **those advantage claims should be discounted accordingly.** Also, the **computational-model contrast is unweighted on both sides**: M-PAGES's Helmert-reduced batch solve + serial per-station processing vs GnssProcessor's per-epoch recursive KF with a *multi-pass* measurement-rebuild loop — neither "richer" nor "simpler" is free, and **neither tree was profiled here.**
