# REORG MAPPING — section → card file, per monolith

Companion to [REORG_PLAN.md](REORG_PLAN.md). One table per monolith, generated by
`python scripts/docs_split.py --tables` from `scripts/docs_map/<stem>.json`; each row
is one contiguous slice of the original, in document order. A target file that
appears twice owns two non-adjacent slices — the document records those cards out of
order, and the split reassembles them.

Regenerate with:

```bash
python scripts/docs_split.py --tables
```

`status` is one of `open`, `closed`, `parked`, `superseded`, `reference`; the finer
verdict a card reached (PROMOTED / KEEP_OFF / FALSIFIED / RECOMMEND_SCOPED) stays in
the card's summary and in its text.
