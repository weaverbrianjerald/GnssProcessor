- **Real-time gap tolerance (fixed in ff1c464, branch fix/realtime; gated 2026-10-17).** With `processing.data_gap_tolerance_s` 0, stepTimeAndDetectGap used 1 s, so every 30 s epoch was a gap and re-seeded the clock from code. It now uses 1.5 times the median measured epoch spacing, never below the former 1 s (which is also the value until a spacing is measured). Without the floor the threshold would be 0.15 s at 10 Hz and 0.75 s at 2 Hz, so one dropped epoch would overwrite the Kalman clock with a single-epoch code clock, a tightening the old rule never made. A stream with a nominal interval of 0.667 s or less (1.5 Hz and faster) therefore keeps the old rule exactly. Above that the threshold is 1.5 intervals, so at 1 Hz it rises from 1 s to 1.5 s and a late epoch (1 s < dt <= 1.5 s) no longer re-seeds the clock.
